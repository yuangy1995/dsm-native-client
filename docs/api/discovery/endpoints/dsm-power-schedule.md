# DSM 电源计划内部 API

## 当前范围与证据

稳定标识 `dsm-power-schedule`，组件 `dsm-core`，内部混合读写能力，风险 `high`。
macOS 支持开机/关机计划的新增、编辑、启停、移除和整体保存。用户已要求开放供测试，
不再设置仅因没有实测而固定关闭的门槛；权限、完整清单、确认和结果核查保留。

2026-10-02/03 在 DSM 7.2.1-69057 Update 12 官方页面核对列表与编辑结构；保存参数
来自官方前端 static 证据，**没有创建、保存或触发真实电源计划**。设备匿名归属待确认，
不提升旧 lab-a 记录。已有 2026-09-26/27 读取证据仍独立保留。

## 请求与响应

| 方法 | API / 版本 | 参数与结果 |
| --- | --- | --- |
| 读取 | `SYNO.Core.Hardware.PowerSchedule.load` v1 | 无业务参数；`poweron_tasks[]` 与 `poweroff_tasks[]` |
| 保存 | 同 API `save` v1 | 两个完整数组，空数组用于移除该类全部计划 |

路径和请求格式由 `SYNO.API.Info` 发现，使用既有 POST 会话构造器。

每项字段：`enabled:Boolean`、`weekdays:String`（数字 CSV，周日=0、周六=6）、
`hour:Int(0...23)`、`min:Int(0...59)`。每天归一为 `0,1,2,3,4,5,6`。
官方前端上限为 **200 条**，不再沿用旧客户端 128 条截断上限。时间是 NAS 本地时钟，
不转换为 Mac 时区；服务端缺失时区时不根据 Mac 猜测。

## 整体保存与安全

- 编辑在本地形成草稿；新增、勾选、编辑或从草稿移除都不会立即写 NAS。
- 只有两个独立数组同时存在、所有条目完整且不超过 200 条，才允许整表保存。旧
  `schedules/items` 摘要仍可读取，但不能作为整表覆盖依据。
- 当前可编辑动作只有开机与关机，规则为每天/每周。一次性、重启、未知动作、未知
  启用状态、非法时间或不完整条目不得被保存流程静默删除。
- 任意条目在同一时分与重叠星期均拒绝，即使动作不同或其中一条停用；与官方编辑器一致。
- 保存确认明确说明计划会使 NAS 无人值守关机、相关服务会中断。
- 提交前复读完整清单并与初始基线做语义比较，忽略临时 ID、数组顺序和星期顺序；
  他处发生变更时拒绝覆盖。客户端每次仅发送一个 save，不并行保存、不自动重试。
- 提交后复读两个数组，完整清单必须与目标一致才确认成功。未知结果保留刷新门闩，
  失败刷新不能解除；再次保存须基于成功刷新后的当前清单。
- 空清单页仍提供添加入口；未知或不完整清单明确解释为何不能覆盖，并给出刷新/DSM 路径。
