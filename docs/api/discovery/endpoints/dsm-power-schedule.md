# DSM 电源计划内部 API

## 标识

| 字段 | 值 |
| --- | --- |
| 端点或端点组标识 | `dsm-power-schedule` |
| 项目组件标识 | `dsm-core` |
| 所属范围 | DSM 控制面板 |
| 能力名称 | 电源计划只读摘要 |
| 分类 | `internal` |
| 操作性质 | `mixed` |
| 风险等级 | `high` |

## 当前证据与启用边界

静态 API 目录只确认 `SYNO.Core.Hardware.PowerSchedule` 存在 `load` 与 `save` 方法，
没有提供版本、参数或响应结构。客户端只启用运行时能力发现明确包含的 v1 `load`；
v1 是保守候选范围，不代表已在当前 DSM build 上验证。`save` 没有进入 Repository
协议、请求契约或界面，始终保持关闭。

## 只读请求与上限

客户端使用运行时发现的路径和请求格式发送一次无业务参数的
`PowerSchedule.load` v1。响应仅从 `schedules` 或 `items` 读取前 128 条，既不自动
翻页，也不持续轮询。服务端报告总数超过可显示数量时，界面提示前往 DSM 查看完整列表。

该请求形态目前只有合成测试，尚未达到 `observed` 或 `read-verified`。

## 响应白名单

每条计划只保留：

- 标识：`id` / `schedule_id`，仅接受字母、数字及 `._-:`；缺失时使用本次快照内的
  合成标识，不作为跨请求写目标；
- 动作：仅解释明确的开机、关机与重新启动别名，其他值统一为未知；
- 状态：`enabled` / `is_enabled`；字段缺失时保持未知，不默认启用；
- 时间：`hour` 必须为 0...23，`minute` 必须为 0...59；
- 一次日期：`date` / `run_date`，仅接受有效 `YYYY-MM-DD`；
- 星期：`weekdays` / `days` / `repeat` 只接受英文命名星期。数字星期存在周日起始
  歧义，当前统一标为未知；
- 根级时区：`timezone` / `time_zone`，仅接受经过字符和长度限制的标识。缺失时界面
  明确显示 NAS 未提供时区，不推断为客户端时区。

命令、脚本、文件路径、账号、主机或网络地址即使出现在响应中也不会进入领域模型。

## 写操作边界

`save` 可能触发无人值守开机、关机或重启，不能复用普通计划任务的保存契约。在取得
版本化参数与响应、动作和时区语义、最大条目数、权限错误、重复提交保护及最终列表回读
证据前，不探测、不发送、不创建猜测 Fixture。未来实现还必须逐项显示变更摘要并要求
明确确认。

## 降级与失败语义

- API 缺失或 v1 不在发现范围时页面独立不可用，且不发送猜测请求；
- 权限、网络、格式或服务错误不阻断硬件设置和其他 NAS 管理页面；
- 时间无效的条目被忽略；未知动作、状态或重复规则以未知展示；
- 空列表只在请求成功后显示为空，不把错误解释为没有计划；
- 手动刷新期间按钮禁用并显示进度，避免重复请求。

2026-09-17 严格读取修正：缺失、畸形或相互冲突的 schedules/items 根不能当作空列表；
小数时间不截成整数，非布尔启用状态保持未知。Windows 单独报告不可显示条目数量，
Mac 将不完整列表标记为需在 DSM 核查，全无可显示项或空列表却报告非零总数时失败，
避免现有空页面误报没有计划。中英文不完整提示不再一律声称已显示前 128 条。

## 客户端与界面

- Apple 领域：`NasPowerScheduleSnapshot`、`NasPowerScheduleEntry`、
  `NasPowerScheduleAction`、`NasPowerScheduleRecurrence`。
- Apple Adapter：`DsmNasAdministrationRepository.loadPowerSchedule()`。
- macOS：NAS 设置中的“电源计划”页，提供全部/已启用/已停用筛选、手动刷新、时区与
  截断说明，以及加载、空内容、筛选空、错误和正常五种状态。
- Windows：固定 v1 读取、128 条边界、字段白名单及原生三态筛选/五态页面已接入，
  只有源码与合成测试证据，没有 save 入口。
- iPhone、iPad、Android：本波不迁移页面，Apple 移动端需回归共享解析修正。
- 状态同时使用图标和文字，不依赖颜色；原生控件保留键盘与 VoiceOver 语义。
