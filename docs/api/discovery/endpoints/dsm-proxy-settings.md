# DSM 互联网代理设置内部 API

## 标识

| 字段 | 值 |
| --- | --- |
| 端点或端点组标识 | `dsm-proxy-settings` |
| 项目组件标识 | `dsm-core` |
| 所属范围 | DSM 控制面板网络代理 |
| 能力名称 | HTTP 代理开关、地址与端口 |
| 分类 | `internal` |
| 操作性质 | `read / write` |
| 风险等级 | `high` |

## 请求契约

| 字段 | 值 |
| --- | --- |
| API 名称 | `SYNO.Core.Network.Proxy` |
| 路径 | 运行时通过 `SYNO.API.Info` 发现 |
| HTTP 方法 | `POST` |
| API 版本 | v1 |
| 鉴权机制 | DSM 会话 Cookie/表单与令牌请求头/表单，不记录值 |
| 内容类型 | `application/x-www-form-urlencoded` |

| 方法 | 参数 | 类型 | 必需 | 含义 | 合成示例 |
| --- | --- | --- | --- | --- | --- |
| `get` | 无 | - | - | 读取代理开关、地址与端口 | - |
| `set` | `enable` | `boolean` | 是 | 启用或停用互联网代理 | `true` |
| `set` | `http_host` | `string` | 启用时 | 不含协议和路径的代理主机 | `proxy.example.invalid` |
| `set` | `http_port` | `integer` | 启用时 | 代理端口 | `3128` |

启用代理时，客户端先去除地址两端空白，拒绝协议、路径、查询、用户信息和内部空白，
并验证端口位于 1 到 65535。客户端不读取、保存或提交代理密码。

## 响应、错误与恢复

读取响应必须包含 `enable`；启用代理时，保存结果按开关、地址和端口三个实际变化字段
分别回读计数。停用代理时只校验开关，不把 DSM 保留的旧地址和端口误判为失败。

| 场景 | 结果语义 | 恢复方式 |
| --- | --- | --- |
| 地址或端口无效 | 提交前确认失败 | 修正地址与端口 |
| API 未发现 | 不支持 | 不发送读取或写请求 |
| 权限不足 | 权限拒绝 | 使用具备网络管理权限的账号 |
| 提交后所有变化字段匹配 | 确认成功 | 使用回读值更新界面 |
| 只有部分变化字段匹配 | 部分成功 | 重新读取开关、地址和端口后逐项核对 |
| 提交断网、超时或响应无效 | 结果未知 | 不自动重放，先重新读取 |
| 回读失败或提交后取消 | 已提交结果未确认 | 恢复连接后重新读取 |
| 同时再次保存 | 重复提交冲突 | 等待当前保存结束 |

## 能力探测与降级

- 未发现 `SYNO.Core.Network.Proxy` 时不读取或提交设置。
- 缺少 `enable` 时视为无效响应，不显示可能错误的状态。
- macOS 本轮按用户明确授权提供测试入口，以实际接口版本、权限、输入、确认、防重复和结果核查判断可用性，不仅因未实测固定关闭。新 DSM build 的真实行为仍待验证；其他平台以其最新授权和实施状态为准。
- 提交前失败可以在修正条件后重试；提交开始后的异常必须先回读。
- 代理设置失败不阻断文件、照片、消息或其他 NAS 设置。
- 当前项目未找到覆盖该控制面板设置的统一公开写 API。

  无基线的旧保存签名仍不支持，不会因旧 NAS 全局开关误发请求。
- iPhone 与 iPad：M6b2 已接原生编辑/确认、原快照绑定、逐请求记录及只读恢复，两端实际 UI、共享和 Mac 回归通过；真实 NAS 写行为未验证。
- 脱敏 Fixture：
  `contracts/request-fixtures/network/set-proxy/synthetic-settings/request.json`。
- 自动化测试覆盖确认成功、超时后部分字段生效、断网且回读失败、无效输入、能力缺失、

  地址规范化、停用时不提交或比较旧地址、输入零请求拒绝和提交/回读双断线不重放。

## 安全与副作用

- 启用或修改代理可能中断 NAS 的更新、套件、通知及其他外网访问。
- Repository 与 macOS 模型共同阻止并发保存。
- 请求 Fixture 只使用 `.example.invalid` 合成地址，不记录真实代理、账号、密码、NAS
  地址、会话或完整 DSM 响应。
- 当前批次不安装代理 CA，不改变证书信任、防火墙、DNS 或默认网关。

- 不同 DSM build、权限、认证代理和直连/QuickConnect 组合下的真实写入副作用尚未验证。
- DSM 对无效域名、IPv6、认证代理和不可达代理的具体错误码尚未收集。
- Android 调用链已迁移但尚未做设备及真实 DSM 写行为验收；Windows 只读适配已增加

  仍关闭；iPhone 与 iPad 的 M6b2 设置链已接入，真实 NAS 写行为尚未验收。
- Windows 实机读取为 `PENDING_USER_VALIDATION`：在已记录版本、具备对应读取权限的
  测试环境核对开关和可用端口；读取失败应提示恢复，不应变为关闭。仅回传版本类别、
  操作和脱敏错误分类，不回传地址、账号或原始响应。写入口继续关闭，不做真实写探测。

用户单独授权修正 Mac 文件服务、终端和代理三个结果判断。页面缓存或回读字段恰好相同，不能覆盖适配器返回的权限拒绝、不支持、部分完成、未知或提交后取消；只有明确成功及提交前取消按对应结果结束。请求、权限检查和服务副作用没有改变，移动本项实现仍按 M6b2 另行推进。三项新增模型回归先复现 18 个错误判断，修复后 Mac 管理模型 101 项、共享完整回归及 Mac 双架构构建通过；真实 NAS 证据等级不提升。具体命令见[移动验证记录](../../../archive/2026-h2/RELEASE_VALIDATION_HISTORY.md#2026-10-05-移动-m6b1-账号与群组管理)。

## 2026-10-05 移动 M6b2 管理与恢复

移动管理读取只使用本文已记录版本；同一解析入口提供严格字段检查，未知开关/非整数端口不能变为可写默认值。新管理方法携带原配置和提交检查点，与 Mac 旧方法共用实际请求编码；旧调用仍保持兼容。开始前核对全部变化组的能力、原字段和依赖，每个写请求前重新检查当前权限并保存记录。明确拒绝不被后续相同配置覆盖；回执丢失只读取，不重复提交。

文件服务的六组请求分别保存写前、接受和回读阶段；未提交的后组不能因读取到相同值而被认领成功。顺序保持 SMB/Time Machine 和在用端口的有效中间状态，无法直接安全交换在用端口时要求用户先明确关闭其中一项。最后一次读取覆盖本次所有已写组。终端和代理以单个完整请求作为恢复单位，若仅部分字段生效，记录该事实并保留整组保护；不能把 SSH 或代理开关相同推定为完整保存。停用代理只发送并比较开关，不改保留地址/端口。

移动的 `NAS/service-operations-v1.json` 仅保存账号上下文/配置摘要、服务类别、逐组阶段/回执和日期，使用完整系统文件保护并排除备份，不存主机、端口正文、账号或密码。准备阶段重启取消；已提交部分等待只读恢复；未完成记录不可直接移除重发。保护仅限制相关服务，读取失败不影响其他页面。实际系统锁屏保护尚待真机验证，模拟器不作通过结论。

本片不新增 DSM 参数，不改变证据等级；五端中 Mac 复用请求并执行回归，iPhone/iPad 增加完整管理与恢复，Windows/Android 只登记语义影响。逐轮测试及设备待办见[移动 M6b2 账本](../../../development/APPLE_MOBILE_MACOS_PARITY_DEVELOPMENT_PLAN_ZH.md#m6b2-文件服务终端与代理)。
