### 同日管理员对照结果

- 新页面的同一 get_user_service 请求成功返回；Session.is_admin=true，DSM 仍为 7.2.1-69057 Update 12。权限表有 25 个键，ActionPrivilege 为空数组；未保存其他真实会话或用户字段。
- File Station、Chat、Drive 授权仍为 true；Download Station 与 VMM 的应用键新增且为 true。
- Container Manager 与控制面板不在管理员 AppPrivilege 表中，但官方主菜单明确显示这两个入口。因此“所有不在 AppPrivilege 的入口都隐藏”会误隐藏管理员管理功能。
- 官方 get_ui_config 的应用定义：Container Manager 的 allUsers=false，未出现 grantPrivilege/advanceGrantPrivilege；控制面板 SYNO.SDS.AdminCenter.Application 同样 allUsers=false，未出现这两个授权字段。VMM 则 allUsers=false、grantPrivilege=all、advanceGrantPrivilege=true；Download Station 为 allUsers=true、grantPrivilege=local、advanceGrantPrivilege=true。
- 这些观察支持区分管理员管理入口与按应用表授权的套件，而不是管理员对所有套件一律放行。定义中的字段语义仍不得脱离版本和页面行为推广到所有应用或委派管理员。
- 官方应用配置声明 Container Manager 24.0.2-1535、VMM 2.6.5-12202；这是应用定义里的版本，不冒充套件中心安装详情复核。
- 首轮管理员事件观察有截断；随后紧跟重载成功捕获目标请求，目标权限摘要捕获批次未截断。没有宣称完整保存了整个启动过程。
- 没有打开控制面板、容器或其他业务页面，只查看菜单和初始化应用定义；原管理员标签保留，额外观察标签在结束前关闭，未导出原始响应或截图。
- 用户补充当前 VMM 是手工安装，该机型不在官方支持范围，另有第三方安装应用；这是用户提供的环境限制，不等同于已核实硬件兼容性。本次 VMM 配置和授权观察不得据此扩展为官方机型支持结论。客户端不按安装来源或机型名单直接判定权限，也不以已安装替代授权；第三方套件未适配时不动态开放原生业务或写操作。
