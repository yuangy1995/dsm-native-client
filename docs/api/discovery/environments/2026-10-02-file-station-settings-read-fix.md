## 证据来源与发现范围

- 目标：核对远程访问账号名单及相关文件设置读取的请求和响应结构，定位客户端解析失败。
- 只观察官方界面产生的读取，必要时查看对应官方静态页面代码；不探测写接口，不保存权限或设置。
- 不导出 HAR，不保存原始响应、凭据、地址、账号、用户路径或文件；仅记录字段名、类型和脱敏合成样本。
- 只记录必要字段结构，不复制地址栏、会话或账号内容到仓库或外部服务。

## 结论

- 官方远程权限名单自然调用 `SYNO.FileStation.VFS.User/get v1`。本机用户和群组分别使用 `type=local`、`usergroup=user/group`、`content=user_settings/group_settings` 及分页参数；群组请求的版本与参数已在官方请求载荷核对。
- 两种名单均返回 `success=true`；`data.offset/total` 为整数，`data.usergrp_settings` 为数组；行的 `name` 为字符串，`enabled/is_modifiable` 为原生布尔。用户行的 `uid` 和群组行的 `gid` 均为十进制数字字符串。此前客户端按整数解码会在得到成功响应后失败，此为当前故障的直接证据。
- 本机两类名单的读取结构达到 `read-verified`，但设备归属未确认，不登记为既有 lab-a 的新验证。域/LDAP、其他套件版本及写操作不据此升级证据等级。
- 为打开官方名单窗口，曾切换未保存草稿中的“指定用户/群组”；完成后取消全部名单窗口，并在父设置选择“不要保存”。没有提交设置或权限写入，也没有导出网络日志。
- 相关分享账号窗口仅作只读查看，本轮未获得可追加的返回结构结论；不据此放宽其解析。
- 真实设置保存、目录服务修改及权限变更不在本次发现范围。

## 传输限速追加核查

- 官方“速度限制设置”的本地用户和本地群组分别自然发起 `SYNO.Core.BandwidthControl/list v1`，用户载荷确认 `protocol=FileStation`、`owner_type=local_user` 及分页参数；群组响应的 `owner_type=local_group`。
- 两类成功响应均存在 `policy=notexist`。`name/protocol/owner_type/policy/schedule_plan` 为字符串，四个 `*_limit_*` 字段为整数，观察到的 `schedule_plan` 为 168 个 `1`。用户响应另有数字 `upload_result/download_result`，群组条目不依赖这两个附加字段。
- 官方用户列表对此显示“应用群组设置”；不能将 `notexist` 默认成 `disabled` 或表示用户实际不限速。客户端原策略枚举缺此值，合成样本已在修复前复现整页 `invalidResponse`。
- 该读取形态达到 `read-verified`；未单独验证群组计算规则、域/LDAP、实际传输速度或任何限速写入。新增两个完全合成的 fixture 仅用于解析回归，证据等级仍为 static。
- 打开名单前只切换父设置中的未保存草稿；完成后取消名单窗口、取消父设置并选择“不要保存”，确认全部草稿窗口已关闭。没有提交 `set`，未导出原始网络日志。
