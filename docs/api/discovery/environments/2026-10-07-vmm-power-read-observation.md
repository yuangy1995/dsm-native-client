## 本次 static 结论

- `Guest.Action.pwr_ctl` v1 逐台 `guest_id/action`，普通 shutdown/poweroff/reboot 设置 900000 ms 等待；poweron 可用 Entry.Request v2 包装。回调成功后只恢复页面轮询，没有读取 task_id 或记录启动时间。前端回调存在不证明服务端已经完成重启。
- 官方虚拟机详情显示字段 `uptime`，展示前执行 `parseInt` 和格式化；这只能证明字段候选，不能证明原生响应类型、单位、来源是宿主进程还是来宾系统，以及 reboot 时是否变化。不能把它直接用作可靠完成依据。
- 当前没有取得可关联本次 reboot 的完成证据；仍 running 只能证明当前状态，不能视为重启完成。客户端可以显示请求已接受、保留未完成记录并只读刷新，不能自动重发或把该缺口伪装为行为验证。
- macOS/Apple 共享电源参数与回执归属按本片修复，移动使用相同安全语义；Windows/Android 仅登记影响，不修改代码。公开 v1 没有 reboot 方法，不能改成强制断电再开机作为替代。
