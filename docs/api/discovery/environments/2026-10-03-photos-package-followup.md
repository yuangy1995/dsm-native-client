## 结论

- 已确认：官方已安装清单的 ActiveInsight 更新候选 install_type 为 system；官方 `_onCheckInstall` 使用 IsSystemInstallType 允许系统套件没有普通 volume_list。客户端原来先强制解析 volume_list，合法系统形状会被拒绝为“信息不完整”。
- 证据等级：候选类型为 read-verified；允许缺省位置的官方分支为 static；`synthetic-system-no-volume` 是完全合成的静态契约样本。没有将这些证据表述为真实 check 响应或本轮更新行为验证。
- 照片观察：在正在运行的上一轮测试包中，照片已显示，点击刷新后底部“无法加载照片库”仍保留；该位置是操作反馈，和图库读取错误区分开。源码确认局部操作的通用解析错误可套用图库错误文案，refresh 未清理终态的 managementMessage/saveMessage。
- 未验证：截图最初失败的是哪一个照片操作，用户尚未提供触发步骤；不据此声称保存、分享或转换等具体 NAS 接口损坏或已被修复。当前明确修复错误归属和过期提示残留。
- 需要在其他版本或权限下复验：新客户端在 NAS 的真实系统套件更新、普通套件及复杂依赖；照片原始触发步骤。
