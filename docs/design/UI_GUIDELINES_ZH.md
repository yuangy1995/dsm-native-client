# 界面与文案指南

本页是五端界面布局、状态与用户可见文案的唯一细则。功能范围见[五端矩阵](../progress/PLATFORM_MATRIX.md)，本地化资源与语言规则见[语言契约](../../contracts/localization/README.md)；协作底线见 [AGENTS.md](../../AGENTS.md)。Android 页面的已确认视觉与交互以[Android 已确认 UI 规范](ANDROID_UI_SPEC_ZH.md)为准。

## 界面与交互

- 界面设计以用户确认的方案和平台原生规范为准；Apple、Android、Windows 分别延续 SwiftUI/AppKit、Jetpack Compose、WinUI 的现有实现。
- UI 建议必须保持平台原生体验，并满足浅色/深色模式、键盘、触控、VoiceOver/屏幕阅读器、动态文字和降低动态效果要求。
- 不得借 UI 修改改变 API、安全策略、Bundle ID、包名、会话存储或业务语义。
- macOS 工作区详情根视图必须占满 `NavigationSplitView` 的可用区域；带标题栏、筛选栏或列表的页面采用顶部对齐。
- SwiftUI 页面级内容统一使用 `fillsAvailableContentArea(alignment:)`；普通空状态居中，标题栏和筛选栏保持 `.topLeading`。
- 新页面必须分别检查加载、空内容、筛选后为空、错误和正常内容五种状态；空状态提供原因和下一步操作，弹窗状态分支占满标题栏以下的剩余区域。

## 面向用户的界面文案

- 所有面向终端用户的标题、字段、按钮、状态、提示和错误信息，默认按普通用户而不是开发者或协议调试人员的理解方式编写。
- 主流程不得直接暴露 API、HTTP 状态、能力发现、build、契约、Keychain、SID、SynoToken、证书钉扎等实现术语；确因安全核对需要展示指纹等技术信息时，必须先给出通俗解释，并将技术细节放在次级层级。
- 不得用“服务端处理、由 NAS 打包、递归、流式、分片、请求往返”等实现过程解释普通功能；默认只说明用户会得到什么、可能受到什么影响以及下一步怎么做。
- 错误信息必须说明“发生了什么”和“用户下一步可以怎么做”，不得只显示内部错误、错误码或无恢复路径的技术描述。
- 按钮名称应描述用户可预期的结果，例如“连接”“重新登录”“保存修改”，避免使用内部动作名称。普通操作不追加“我已核对”等重复勾选；额外确认必须说明具体风险，不能泛称“影响”。
- 照片页不常驻显示“照片空间”“个人空间”“本人空间”等重复标签；只在存在实际可切换来源时提供简洁入口，使用“我的照片／共享照片”说明选择，不暗示可访问他人私人照片。
- 同一工具栏的按钮使用一致样式与点击区域；面包屑支持整块点击、键盘与长路径，并优先合并已有操作栏，避免单独占行。
- 新增或修改界面时必须审查全部可见文案；开发诊断信息只进入受控日志或可选的高级详情，不得混入默认用户界面。
- 常驻页面避免教学式、重复解释式提示；控件和标题已表达清楚的内容不再另加说明。仅保留必要的操作限制、风险确认和错误恢复提示，并使用简短文案。
- 日常界面不得使用“待确认”“待核对”“核对结果”“验证中”等开发、测试或内部结果复核用语，也不要求用户协助验收或检查请求结果。界面只表达用户可理解的业务状态和恢复操作；不确定结果、防重复提交与后续恢复由程序内部处理，不得因此误报成功、失败或削弱安全检查。
