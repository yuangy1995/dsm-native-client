# macOS 桌面云盘发布与升级验收

本文定义桌面云盘发布候选版本的签名、公证、升级和 Finder 实机验收。自动化测试、
合成基准和无签名构建只能作为前置证据，不能替代正式签名包与真实 NAS 验收。

每次执行使用全新副本保存结果，未执行项写“未验证”及原因。测试只使用专用账号、
专用目录和可丢弃数据；不得记录 NAS 名称、地址、QuickConnect ID、账号、路径、
文件名、SID、SynoToken、Cookie、DID、序列号、MAC 或原始响应。

## 发布包流水线

1. 在干净工作区运行全部仓库检查和 Apple 测试。
2. 使用 `apple/Apps/DsmMac/package.sh` 选择 Developer ID Application 证书生成
   App 与 DMG。临时签名包会移除 File Provider 扩展，不能用于云盘验收。
3. 本地发布事先使用 `xcrun notarytool store-credentials` 将 API Key 凭据保存到登录
   钥匙串；GitHub 发布则由受保护 Environment Secret 在临时钥匙串中配置。仓库、
   命令行参数和日志中不得出现 API 私钥或其正文。完整变量清单见
   [GitHub Actions Apple 签名与发布配置](../development/APPLE_GITHUB_ACTIONS_SIGNING_ZH.md)。
4. 设置 `LANSTASH_NOTARY_PROFILE`，运行
   `apple/Apps/DsmMac/notarize.sh <DMG>`，等待公证、装订票据并完成 Gatekeeper、
   权限和扩展校验。
   已配置受控 `macos-release` 环境与发布 Secrets 时，也可手动触发
   `.github/workflows/macos-release-verification.yml` 执行同一签名、公证和严格校验；
   缺少这些前置条件时该工作流必须失败，不能用日常临时签名产物替代。
5. 保存发布版本、构建号、源码提交、安装包 SHA-256 和下表的脱敏结论。不得保存
   签名凭据、NAS 地址、账号、映射名称或真实路径。

## 升级兼容矩阵

每个候选版本至少覆盖下列组合。没有实机证据时必须写“未验证”，不能从其他组合
推断通过。

| 维度 | 最低组合 | 需要记录 |
| --- | --- | --- |
| App 安装 | 上一个公开版本原位升级、全新安装 | 映射是否保留、重复域是否出现、卸载后的预期行为 |
| macOS | 14、15、当前最新稳定大版本 | 系统版本类别、Apple 芯片/Intel、Finder 与扩展状态 |
| 缓存位置 | 系统磁盘、macOS 15+ 合格外置卷 | 拔出、重新接入、空间不足与恢复 |
| 连接方式 | 局域网直连、QuickConnect 直连或中继 | 只记录连接类别，不记录地址或 ID |
| 证书 | 公共 CA、自签名或私有 CA | 只记录证书类别和用户确认结果 |
| 目录规模 | 1 千、1 万、10 万合成项目 | 首屏、连续滚动、取消、内存压力和恢复 |
| 文件下载 | 小文件、大文件、中断续传 | 进度、取消、续传起点和最终内容一致性 |
| 离线保留 | 文件、目录、取消、空间不足 | 计划、下载、释放、重启后的状态 |
| 生命周期 | Finder 重启、App 重启、系统重启、睡眠唤醒 | 域是否重复、任务是否泄漏、状态是否恢复 |
| DSM | 当前维护基线及计划支持的其他 build | DSM 完整版本类别、File Station 版本和证据等级 |

升级前后必须确认映射稳定标识、Finder 入口、暂停状态、缓存位置策略和已完成缓存
记录的兼容性。不得通过删除配置或重新创建映射掩盖迁移问题。

## Finder 实机检查

- 添加、打开、暂停、继续和移除映射；移除前确认没有仍在进行的离线任务。
- 在大目录中滚动和切换层级，然后离开页面，确认枚举能够取消。
- 中断大文件下载后再次打开，确认复用稳定暂存文件且最终结果完整。
- 取消保留离线后确认没有继续增长的进度；再次执行可完成并可释放本地副本。
- 制造可恢复的网络中断、登录失效和空间不足，界面应说明发生了什么以及下一步。
- 导出诊断摘要，检查其中没有 NAS 名称、地址、账号、映射标识、路径、文件名或
  日志正文。

## 正式签名详细验收清单

### 1. 安装、签名与扩展注册

- 全新安装正式签名版本，确认签名链、entitlement、嵌入扩展和 Team ID。
- 确认 File Provider Extension 被系统识别，Finder“位置”显示映射。
- 分别添加整个 NAS、单目录和同一 NAS 的多个非重叠映射，再逐一移除。
- 删除 App 后确认没有不可恢复的孤立 domain；重装不应意外恢复已删除映射。
- 核对主 App 与 Extension 的 Bundle ID、App Group 和 Keychain Access Group。
- 验证公证、staple 和 Gatekeeper；临时签名包不得用于本节结论。

### 2. App Group 与共享 Keychain

- 主 App 写入映射和 runtime 后，Extension 能读取；Extension 更新的 runtime 能被
  主 App 读取。
- 验证 schema 升级和覆盖安装后的共享容器保留；App Group 不可用时应在开始前禁用
  云盘，而不是运行到中途失败。
- 创建首个映射后写入最小必要会话，Extension 能读取；共享 Keychain 中不得出现
  密码或 OTP。
- SID 和 SynoToken 按 profile 隔离，多 NAS 不串用；显式退出、会话失效、删除 NAS
  或删除最后一个映射后按策略清理。
- 模拟访问组权限失败和旧安全存储迁移失败，界面应说明重新登录或恢复方法。

### 3. Domain 与进程生命周期

- 关闭主窗口、完全退出主 App、系统终止 Extension、Finder 重启后分别检查映射。
- 覆盖 Mac 重启、用户注销登录、睡眠唤醒、NAS 重启和临时断网。
- 覆盖 Wi-Fi/有线切换、局域网地址变化和 QuickConnect 直连/中继变化。
- 记录一个同步锚点后，在同一目录执行远程创建、修改、改名和删除；分页读取变化并重启
  Extension 后继续。裁剪、升级或损坏锚点时应触发完整重新枚举，而非静默遗漏变化。
- App 与 Extension 短暂版本不一致时应安全失败，不得损坏配置或重复创建 domain。
- 删除映射期间仍有下载任务时，先取消任务，再完成 domain 与本地状态清理。

### 4. 文件读取、进度、取消与续传

至少使用 1 KB、10 MB、1 GB、10 GB 和 50 GB 的可丢弃文件，记录规模类别，不记录
文件名或校验值。逐项确认：

- 首次打开耗时和 Finder 进度连续性；
- 取消后 Swift Task 与网络传输停止，部分暂存可按策略保留；
- 再次打开或断网恢复后从稳定暂存进度继续；
- App 退出时继续或安全中止，不留下无法恢复的任务；
- 远端文件大小或修改时间变化后隔离旧暂存；
- requested version 失效时不返回旧内容；
- 完成后的文件大小和内容一致性校验通过。

### 5. 缓存卷与空间

分别覆盖系统盘、内置其他 APFS 卷、外接 APFS SSD 和不合格可移动卷：

- 正常挂载、下载中拔出、App 关闭时拔出、重启时缺失和稍后重新接入；
- 卷名称变化、UUID 保持不变和 UUID 变化；
- 外接卷空间不足、系统盘空间不足但外接卷充足；
- 暂存位置、File Provider 最终物化的峰值空间和释放后的记录一致性；
- 不合格卷必须在选择阶段被拒绝，并提供可理解的下一步。

### 6. 大目录与资源基线

使用 100、1,000、10,000 和 100,000 个合成项目，记录：

- 首屏与完整分页耗时、API 请求次数和重复刷新；
- 元数据缓存命中、singleflight 合并和离开目录后的取消；
- Extension 与主 App 内存峰值；
- QuickConnect 下的响应和 NAS 唤醒频率。

性能结果应与
[桌面云盘合成性能基准](../quality/DESKTOP_CLOUD_DRIVE_BENCHMARK_ZH.md)
分开记录；合成基准不能代替 Finder 实测。

### 7. 特殊项目

- 超长名称和完整路径；
- 中文、英文、日文、emoji 与不同 Unicode 规范化形式；
- 大小写相近名称、无扩展名、多点扩展名和含空格名称；
- 损坏或无法解码的名称、无权限条目和单个异常条目；
- 枚举过程中新增、删除文件或目录。

单个异常项目不得导致整个可读目录消失；无法安全表示的名称必须给出稳定失败语义。

### 8. 离线保留

- 单文件、单目录和整个映射；
- 递归空间预检、扫描取消、下载取消、部分完成后重启；
- 断网后读取已完成项目；
- 父子目录重复固定，以及释放子目录、释放父目录；
- 临时缓存和离线缓存区分，LRU 不得删除固定项目。

### 9. 升级、迁移与回退

- 从上一个公开版本创建映射并产生临时缓存、离线内容，再覆盖安装候选版本。
- 验证 mapping ID、domain identifier、item identifier、共享会话和 runtime schema。
- 确认离线内容仍可访问，移除映射仍能完整清理。
- 候选版本失败后按发布说明回退，记录旧版是否能读取新 schema；不能通过删除配置
  掩盖不兼容。

### 10. 故障恢复与孤立状态

通过专用测试构建或可控系统条件覆盖：

- mapping 存在但 domain 不存在；
- domain 存在但 mapping 不存在；
- mapping 停留在创建或移除状态；
- mapping 存在但共享会话缺失；
- 没有 mapping 但共享会话仍存在；
- 暂存文件不存在所属 mapping；
- runtime schema 无法读取。

每个场景记录系统是继续、回滚、隔离还是要求重新认证。不得直接删除未知系统目录
作为恢复步骤。

## Beta 发布出口

首个正式签名包先作为 Beta，不直接标记稳定。随包提供：

- 只读、大文件完整物化、外置缓存卷等已知限制；
- 本文测试清单和结构化社区报告入口；
- 诊断导出的内容、隐私边界和提交方法；
- App 内移除异常映射、确认 Finder 入口消失的安全清理步骤；
- 升级、回退和 schema 兼容说明。

只有正式签名验收通过并关闭阻断问题后，才能增加 `DEVICE_VERIFIED`；社区结果按独立
报告审核，不能替代维护者验收或自动提升为 `STABLE`。

## 五端影响

File Provider 桌面云盘只在 macOS 实现。iPhone、iPad、Android 和 Windows 的普通
文件功能及契约不变；社区测试中的 `desktop-drive.*` 在这些平台记录为
`not-supported`。若未来在其他桌面端实现同类系统集成，必须新建平台计划，不能
直接复用本表中的 macOS 通过结论。

## 正式签名现场执行矩阵

以下保留原现场用例 ID、步骤和判定；其只读场景在关闭编辑/删除的映射中执行。写入场景另按当前云盘计划授权，不以旧只读用例覆盖当前写回验收。

### 1. 执行前提

- 使用 Developer ID Application 正式签名并完成公证、票据装订和 Gatekeeper 校验的
  安装包；临时签名包不得用于本矩阵。
- 使用专用测试 Mac、专用 NAS 账号、可丢弃共享目录和可恢复外接卷；测试数据不得
  包含真实用户文件。
- 升级与回退前分别保存可恢复的测试环境快照。快照只能包含测试配置和虚构数据，
  不得包含 Keychain 导出、密码、会话或原始 NAS 响应。
- 测试 Mac 应至少保留一条管理员恢复路径。不得为了修复测试状态直接删除未知的
  File Provider 系统目录。
- 记录当前源码提交、安装包 SHA-256、App 版本/build、macOS 大版本与架构类别、DSM
  完整版本和 File Station 版本；设备、连接和证书只记录类别。

### 2. 状态与证据规则

| 状态 | 判定规则 |
| --- | --- |
| 通过 | 本用例全部步骤在当前记录的环境完成，预期结果均满足，并已留下最小脱敏证据 |
| 失败 | 任一步出现不符合预期的结果；即使重试后通过，也保留首次失败并关联缺陷编号 |
| 未执行 | 没有执行、环境不适用或前置条件不满足；必须填写原因和后续条件 |

每条用例至少记录以下字段：

| 字段 | 内容 |
| --- | --- |
| 用例 ID | 本文固定 ID，不自行改名 |
| 状态 | 通过 / 失败 / 未执行 |
| 执行时间 | 日期与时区，不记录精确位置 |
| 执行人 | 项目内稳定别名，不记录私人账号 |
| App | 版本、build、源码提交、安装包 SHA-256 |
| 环境 | macOS 大版本、架构类别、DSM 完整版本、File Station 版本 |
| 条件类别 | 安装方式、连接方式、证书类别、缓存卷类别、目录/文件规模类别 |
| 观察结果 | 用户可见结果和最终状态，不粘贴原始日志或响应 |
| 证据引用 | 脱敏截图编号、测试报告编号或缺陷编号；不得使用含秘密的本地绝对路径 |
| 清理结果 | 已完成 / 失败；失败时记录安全恢复步骤和剩余影响 |
| 未执行原因 | 仅状态为“未执行”时必填 |

单元测试只能作为“前置自动化”附加引用，不能把用例状态提升为“通过”。截图必须先
检查菜单栏、Finder 侧栏、窗口标题和文件列表，避免泄露设备名、NAS 名称或文件名。

### 3. 安装、签名与 Extension

| ID | 操作 | 通过条件 | 状态 |
| --- | --- | --- | --- |
| SIG-01 | 在未安装岚仓的测试用户中安装候选包 | Gatekeeper 接受，App 可启动，签名链、公证与票据有效 | 未执行 |
| SIG-02 | 核对主 App 内嵌的 File Provider Extension | Extension 存在、签名团队一致、系统可识别，不依赖临时签名降级 | 未执行 |
| SIG-03 | 创建“全部共享文件夹”映射 | Finder“位置”出现一个可浏览入口，创建时不下载文件正文 | 未执行 |
| SIG-04 | 创建单目录及同一 NAS 的非重叠映射 | 每个 domain 唯一，无重复入口或静默覆盖 | 未执行 |
| SIG-05 | 逐一移除映射并重新启动 App/Finder | 对应入口消失，其他映射不受影响，不留下不可恢复孤立 domain | 未执行 |
| SIG-06 | 卸载后重装同一候选版本 | 不意外恢复已明确删除的映射；保留行为与发布说明一致 | 未执行 |

### 4. App Group 与共享 Keychain

只观察“能否读取”和“是否按策略清理”，不得导出或查看会话正文。

| ID | 操作 | 通过条件 | 状态 |
| --- | --- | --- | --- |
| SHD-01 | 主 App 创建映射，随后由 Finder 枚举 | Extension 可读取映射与非秘密索引；主 App 能看到 Extension 更新的 runtime | 未执行 |
| SHD-02 | 覆盖安装候选版本后重新浏览 | App Group 数据按 schema 策略保留，未损坏或生成重复 domain | 未执行 |
| SHD-03 | 在 App Group 不可用的受控条件下启动 | 创建入口在开始前禁用或给出恢复方法，不运行到下载中途才失败 | 未执行 |
| SHD-04 | 创建首个映射后通过 Finder 读取文件 | Extension 可获得最小必要会话；共享安全存储中没有密码或 OTP | 未执行 |
| SHD-05 | 配置两个专用 NAS profile 并交替读取 | 会话按 profile 隔离，不串用身份或权限 | 未执行 |
| SHD-06 | 分别执行显式退出、会话失效、删除 NAS、移除最后映射 | 会话按既定策略清理；仍有其他映射时不误删共享会话 | 未执行 |
| SHD-07 | 模拟访问组权限或旧安全存储迁移失败 | App 保留映射并提示重新登录/恢复，不显示内部凭据或错误正文 | 未执行 |

### 5. App、Finder、Extension 与系统生命周期

| ID | 操作 | 通过条件 | 状态 |
| --- | --- | --- | --- |
| LIFE-01 | 关闭最后一个主窗口后从 Finder 浏览 | App 按产品设计后台运行，映射保持可用 | 未执行 |
| LIFE-02 | 从菜单显式退出主 App 后请求新在线内容 | Extension 安全拒绝新的在线读取；已完整缓存内容按设计保持可读 | 未执行 |
| LIFE-03 | 系统终止 Extension 后再次浏览 | Extension 可恢复，不重复 domain，不丢失映射状态 | 未执行 |
| LIFE-04 | 分别重启 Finder、主 App 和 Mac | 状态恢复且不误报，无泄漏任务或重复入口 | 未执行 |
| LIFE-05 | 用户注销再登录、睡眠再唤醒 | 未手动暂停的映射恢复；手动暂停状态不被清除 | 未执行 |
| LIFE-06 | NAS 重启、临时断网、Wi-Fi/有线切换 | 已缓存内容和在线状态按设计降级/恢复，错误提供下一步 | 未执行 |
| LIFE-07 | 下载期间移除映射 | 先停止新的请求并完成可恢复清理；不得把系统取消请求冒充已停止传输 | 未执行 |

### 6. 固定规模文件读取、取消与续传

使用 1 KB、10 MB、1 GB、10 GB、50 GB 五种可丢弃文件。只记录规模类别和“一致/

### 11. 清理、回滚与停止条件

每轮结束按以下顺序清理，并在记录中逐项确认：

1. 停止新的离线保留、下载和目录压力任务，等待可观察任务结束或记录无法确认。
2. 在 App 内释放本轮临时/离线测试内容；不得用普通递归删除代替 File Provider 释放。
3. 在 App 内移除本轮映射，确认 Finder 入口消失；其他映射不得受影响。
4. 删除 NAS 上的可丢弃测试数据，并通过 NAS 只读列表复查；此步骤不得与本地缓存清理
   混为同一操作。
5. 恢复外接卷、网络、磁盘空间和测试账号的初始状态。
6. 删除仅含脱敏结论的临时截图副本之外的现场生成物；不得保留原始日志、Keychain
   导出、Finder 数据库、未脱敏响应或真实路径。

出现以下任一情况立即停止当前批次并回滚：

- 正式签名、公证、entitlement、App Group 或共享 Keychain 身份不一致；
- 映射移除可能影响非测试数据，或发现 NAS 远端内容被缓存释放操作修改；
- 外接卷异常导致系统盘产生隐式第二份映射或无法确认真实落盘位置；
- 升级/回退可能覆盖唯一配置副本，或旧版无法读取且没有安全恢复快照；
- 证据采集界面出现真实凭据、用户数据或无法脱敏的系统信息。

回滚只使用发布说明、App 内恢复入口、重新安装已保存的正式包和执行前测试快照。
不得直接删除未知 App Group、Keychain 或 File Provider 系统数据来制造“恢复成功”。
无法完成清理时，将相关用例标记“失败”，记录剩余影响和下一步，不得标记“未执行”。

### 12. 隐私排除项

证据、文件名、截图、问题单和提交记录中不得出现：

- 密码、OTP、SID、SynoToken、Cookie、DID、证书私钥或 Keychain 正文；
- NAS/设备名称、地址、QuickConnect ID、账号、真实共享名、真实路径和文件名；
- 卷 UUID、序列号、MAC、Team ID 全值、个人 Apple ID 或签名凭据；
- 原始 DSM 响应、原始 File Provider 日志、崩溃转储或未脱敏诊断；
- 测试文件校验值正文、测试数据正文或能够反推出测试环境身份的组合信息；安装包 SHA-256 可按本矩阵的证据要求记录。

设备、连接、证书和缓存位置只记录类别；稳定区分多台 NAS 时使用 `lab-a`、`lab-b`
等无设备信息别名。需要证明内容一致时只记录“一致/不一致”和所用算法类别，不记录
校验值。
