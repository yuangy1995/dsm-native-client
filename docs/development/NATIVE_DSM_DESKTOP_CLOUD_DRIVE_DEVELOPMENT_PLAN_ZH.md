## 2. 已确认的产品决策

1. 接受 Finder 和 Windows 文件资源管理器中的原生“云盘位置”，不要求 macOS 独立卷或 Windows 盘符。
2. 第一版只提供只读映射。
3. 默认只加载目录与文件元数据，不主动下载文件内容。
4. 用户打开文件时按需下载；用户可对文件或目录选择“始终保留在本机”。
5. 用户可映射当前账号可见的全部 NAS 共享文件夹，也可只映射一个共享文件夹或子目录。
6. 点击主窗口关闭按钮不退出应用；应用继续在后台维护映射。只有用户从托盘、菜单栏或系统应用菜单明确选择退出，或由操作系统结束进程时才退出。
7. 应用提供每个映射的缓存位置、缓存用量、临时缓存上限、离线保留用量和清理能力。
8. 手动缓存前必须完成远端大小与本地空间检查；空间不足时不得开始，并提供更换缓存磁盘、减少选择内容和清理缓存的恢复入口。

## 3. 目标与非目标

### 3.1 首版目标

- 在 Finder 和文件资源管理器中展示 NAS 文件树。
- 文件内容默认保持“仅在线”状态。
- 打开文件时透明下载到本地。
- 支持文件和目录递归固定为离线可用。
- 支持将临时缓存安全释放为仅在线状态。
- 按映射统计缓存大小并提供软上限。
- 提供明确、可恢复且可访问的同步状态。
- 支持网络中断、休眠唤醒、会话过期和缓存磁盘断开后的安全降级。
- 主窗口关闭后继续后台运行，并提供显式退出。
- 保持 NAS 文件为事实来源，不把本地缓存当作独立副本或备份。

### 3.2 首版非目标

- 不提供独立卷、盘符或第三方文件系统驱动。
- 不支持从 Finder 或文件资源管理器创建、修改、重命名、移动或删除 NAS 内容。
- 不支持离线编辑、写回、双向冲突合并或跨设备锁。
- 不承诺 NAS 远端变化实时到达；首版使用访问时刷新、周期检查和手动刷新。
- 不映射 DSM 系统根目录、真实卷路径、隐藏系统文件或当前账号无权访问的目录。
- 不通过未验证的内部 API 获取增量日志或变化通知。
- 不将“离线可用”宣传为备份。

## 4. 名词与用户语义

| 名词 | 用户含义 | 技术含义 |
| --- | --- | --- |
| 映射 | 在系统文件管理器中显示一个 NAS 位置 | 一个 File Provider Domain 或 Cloud Files Sync Root |
| 整个 NAS | 当前账号在 File Station 中可见的全部共享文件夹 | `list_share` 返回且权限允许的共享目录集合 |
| 文件夹映射 | 一个共享文件夹或其子目录 | 映射的远端根路径 |
| 仅在线 | 可看到名称和大小，但内容尚未下载 | dataless item 或 placeholder |
| 临时缓存 | 因访问而下载，可由应用自动释放 | 已物化但未固定的内容 |
| 离线保留 | 用户明确要求始终保留 | pinned 或用户固定的已物化内容 |
| 释放本地空间 | 删除可重建的本地内容，保留远端文件 | evict、dehydrate 或恢复为仅在线 |
| 缓存位置 | 存放映射本地内容的磁盘 | 系统允许的 File Provider 域卷或同步根所在卷 |

面向用户的界面不显示 hydration、dehydration、placeholder、domain、sync root 等实现术语。

## 5. 当前仓库基础与差距

### 5.1 macOS 可复用基础

- 已有 File Station 共享目录和文件夹分页浏览。
- 已有文件下载、Range 分段下载、断点恢复、进度和取消。
- 已有递归遍历目录并汇总文件大小的实现。
- 已有应用存储占用统计与可再生缓存清理界面。
- 已有应用内 AES-GCM 加密会话、证书策略和 QuickConnect 连接链路。
- 当前 `applicationShouldTerminateAfterLastWindowClosed` 返回 `true`，需要改为窗口关闭后继续运行。

### 5.2 Windows 可复用基础

- 已有 WinUI 3 应用壳层和文件列表。
- 已有 File Station 列表、搜索、重命名与受保护删除的部分领域契约。
- 已有凭据管理器会话和 QuickConnect 连接链路。
- 当前没有 Cloud Files API 适配层、文件内容下载流、目录大小估算、缓存统计、托盘或关闭拦截。

### 5.3 当前剩余差距

- File Station 公开接口仍没有经过验证的稳定增量变化源；首版保持访问时刷新、恢复检查和非实时语义。
- Windows 非法名称转义、保留设备名和大小写碰撞已有确定性实现与单元测试，Shell 实际显示仍需验证。
- 外置缓存磁盘拔插、安装升级/卸载恢复、系统重启与双架构行为仍需实机结论。
- Windows 同步根对本地未跟踪新文件的阻止边界仍需用常见应用验证；当前已确保占位文件只读、拒绝重命名和删除，并且不存在任何 NAS 写回通道。

## 6. 平台能力验证结论

### 6.1 macOS

项目最低版本是 macOS 14.0。使用本机 Xcode 26.6、macOS 26.5 SDK 进行了声明检查和 Swift 类型检查：

- Replicated File Provider 可作为 macOS 首版基础方案。
- `NSFileProviderDomain(displayName:userInfo:volumeURL:)` 的可用性是 macOS 15.0+。
- `NSFileProviderManager.checkDomainsCanBeStoredOnVolume(at:)` 的可用性是 macOS 15.0+。
- 将上述调用放入 `if #available(macOS 15.0, *)` 后，可以以 macOS 14.0 为部署目标通过类型检查。
- 不需要为了外部缓存磁盘能力提高项目最低系统版本。

因此采用以下兼容策略：

| 系统版本 | 缓存位置 |
| --- | --- |
| macOS 14 | 仅使用系统管理的默认磁盘位置 |
| macOS 15+ | 默认使用系统磁盘；允许选择经系统资格检查通过的其他磁盘 |

外部磁盘的真实创建、拔出、重新接入和跨设备行为尚未实机验证，实施时必须使用 APFS、常见外置 SSD 和不合格卷分别测试。

### 6.2 Windows

Cloud Files API 从 Windows 10 1709 起支持同步根、占位文件和按需内容；当前项目最低版本为 Windows 10 2004，因此版本门槛满足。

以下内容只完成官方 SDK 文档核对，尚未在 Windows 设备实机验证：

- 当前未打包 WinUI 3 应用注册同步根的完整安装与卸载流程。
- 系统盘、其他固定磁盘和移动磁盘的支持边界。
- x64 与 arm64 的回调、Shell 状态图标和资源管理器重启恢复。
- 托盘常驻、开机启动和显式退出后的同步根状态。

Windows 实施必须先做无真实 NAS 数据的本地占位文件原型，再接入 Repository。

## 7. 总体架构

```text
Finder / 文件资源管理器
        │
        ▼
平台文件提供层
macOS File Provider / Windows Cloud Files Adapter
        │
        ▼
Desktop Cloud Drive Domain
映射、项目、状态、空间检查、缓存策略
        │
        ▼
只读 File Repository
目录枚举、文件信息、内容读取、远端刷新
        │
        ▼
现有认证、连接解析与 File Station 官方 API
```

### 7.1 共享领域层职责

- 映射配置与生命周期。
- 远端项目标识、目录枚举和内容版本。
- 缓存请求、大小估算和磁盘空间决策。
- 平台状态到统一用户状态的映射。
- 远端刷新计划和退避。
- 错误分类、恢复动作和诊断摘要。

### 7.2 平台适配层职责

- 注册、连接、暂停和移除系统云盘位置。
- 创建目录与文件占位项。
- 响应系统的枚举和内容读取请求。
- 报告下载进度、固定状态和同步状态。
- 将本地内容安全恢复为仅在线。
- 监听磁盘、网络、休眠、唤醒和系统退出事件。
- 拒绝首版所有写请求。

### 7.3 不允许的耦合

- File Provider Extension 不直接依赖 SwiftUI 页面状态。
- Windows Cloud Files 回调不直接操作 WinUI 控件。
- 平台占位文件身份中不保存密码、SID、SynoToken、Cookie、主机或真实账号。
- UI 不直接调用 DSM API。
- 缓存清理不使用普通递归删除绕过平台文件提供器。

## 8. 建议的领域模型

### 8.1 `DesktopDriveMapping`

```text
id: UUID
profileID: UUID
displayName: String
scope: allShares | folder
remoteRoot: RemoteLocation
accessMode: readOnly
cachePolicy: MappingCachePolicy
launchAtLogin: Bool
createdAt: Date
state: MappingState
```

### 8.2 `MappingCachePolicy`

```text
location: systemDefault | eligibleVolume(opaqueVolumeID)
temporaryLimitBytes: Int64
minimumFreeReserveBytes: Int64
evictionPolicy: leastRecentlyUsed
```

卷标、用户选择路径或系统实际缓存路径不得作为跨设备稳定身份。macOS 使用安全书签或系统提供的卷标识；Windows 使用不含用户目录隐私的卷标识和受控同步根配置。

### 8.3 `MappedItem`

```text
itemID: OpaqueItemID
mappingID: UUID
parentID: OpaqueItemID
remotePath: String
name: String
kind: file | folder
sizeBytes: Int64?
modifiedAt: Date?
contentVersion: OpaqueVersion
capabilities: read | enumerate
```

首版无法确认 File Station 是否能提供跨重命名稳定的公开文件标识。若只能使用规范化路径生成身份，则远端重命名按“旧项目消失、新项目出现”处理，不能承诺保留原项目的临时缓存或固定状态。任何改进必须先验证公开字段，不能虚构 inode 或文件 ID。

### 8.4 `MappingState`

```text
preparing
available
checking
paused
offline
authenticationRequired
cacheVolumeUnavailable
insufficientLocalSpace
degraded
recoveryRequired
removing
failed
```

创建和移除已经接入独立事务协调器，并通过可注入的 domain controller、安全会话
存储和配置存储验证以下边界：

- 会话保存失败时不得注册 domain；
- mapping 保存后 domain 注册失败时回滚；
- domain 注册成功但 runtime 保存或可读验证失败时回滚；
- 移除开始后持久化 `removing`，失败时保留足够信息供下次启动继续清理；
- 系统盘 mapping 存在但 domain 不存在时补注册；
- domain 存在但没有任何 mapping 时清理孤立 domain；
- 外接缓存卷 domain 缺失时保持不可用，不错误迁移到系统盘；
- runtime 中单条记录无法解码时保留连接、mapping 和其他健康记录，仅将对应 mapping
  标记为 `recoveryRequired`，由用户明确重新连接后重建本机状态；恢复标记使用旧版会
  忽略的独立字段，底层 runtime 保持旧版可解码的 `failed`，避免回退版本时整份配置
  因新增枚举值而无法读取；
- 共享会话缺失或发布失败时保留 mapping，进入 `authenticationRequired` 并提示重新登录；
- 启动时先续清 `removing`，只对仍需使用的 mapping 发布共享会话，避免会话失败阻断
  本地清理或把刚移除的会话重新写回；
- `failed` 且 domain 已存在的 mapping 会在下次启动重新验证，不再永久跳过；
- `recoveryRequired` 只允许通过“发布会话、重连、可读验证、原子提交”显式清除；
  普通暂停、检查、缓存或离线状态写入不会提前移除恢复标记；
- 移除最后一个 mapping 时先清理共享会话；清理失败则保留 `removing`，下次启动续清，
  避免配置已经消失却留下无法追踪的会话；创建回滚或空映射启动时若共享会话删除
  失败，则通过 profile 级待清理标记在下次启动继续，删除确认成功后才清除标记；
- 配置 Store 强制校验运行时状态转换，`recoveryRequired` 只能通过显式恢复事务清除，
  `removing` 不能被普通运行时写入恢复为活跃状态；读取已成功配置后发生瞬时损坏或
  文件消失时，只读操作可使用当前进程内的最后成功快照，写操作仍拒绝覆盖异常文件；
- 主 App 已将逐项释放、下载请求、重连、根目录通知、容量读取、时钟和轮询等待封装
  为可注入系统边界，并用 fake 单元测试验证部分释放、容量不足、下载请求失败、任务
  取消、确定性超时、重连失败以及再次加载失败时的 App 状态和本地回滚；配置 Store
  也通过协议注入覆盖缓存记录提交失败、暂停/恢复提交失败和 pin 回滚失败，补偿失败时
  不再显示成功；
- 主 App 在初始确认、写入 pin 后、每个 `requestDownload` 前和每轮完成状态轮询时按
  最新 runtime 与卷容量重新计算；已经完整缓存的字节不重复计入，也不会重复请求；
- File Provider Extension 的实际 `fetchContents` 在每次 repository 下载前检查容量；
  下载进度达到或跨过新的 8 MiB 检查阈值时，按当前剩余字节复查容量；容量下降时
  取消当前下载 Task，等待下载调用返回后清理 partial 和临时文件，不写入完成缓存记录；
- 临时内容下载前先执行缓存软上限准入：只按 LRU 驱逐临时条目，驱逐和配置记录删除
  逐项成功后才开始新下载；显式串行化并发准入并预留在途额度，已有完整 staging 文件
  也不能绕过准入，同一路径的记录与预留不重复计数；始终离线条目不参与驱逐，任一步
  失败均保守拒绝接收正文；
- 外接卷资格、挂载名称和不可用状态已纳入可注入边界，断开时不会把卷标识作为面向
  用户的名称显示。

上述 fake 与 Extension 单元测试只证明调用顺序、下载 Task 收到取消、错误处理和本地
状态，不代表 macOS 已停止系统层传输，也不代表 Finder、真实卷、App Group 或共享
Keychain 行为已经验证。卷重连后的首次实际内容下载会重新经过容量与软上限准入，但
仍需通过正式签名验证系统调度、真实卷容量、物理释放、孤立 domain 和系统取消行为。

## 9. 映射创建流程

### 9.1 向导步骤

1. 选择 NAS。
2. 选择“全部共享文件夹”或“指定文件夹”。
3. 选择显示名称。
4. 选择缓存磁盘。
5. 设置临时缓存上限。
6. 显示只读说明和后台运行说明。
7. 执行权限、路径、重叠映射、缓存磁盘和系统能力检查。
8. 创建系统云盘位置。
9. 枚举根目录元数据并显示完成结果。

复杂选项使用渐进披露。主流程只显示一个主要操作“创建云盘位置”，高级设置默认折叠。

### 9.2 全部共享文件夹映射

- 根目录下展示当前账号可见的共享文件夹。
- 不展示未授权、隐藏系统共享或无法通过 File Station 正常列出的内容。
- 共享列表变化在刷新后增删占位目录。
- 某个共享目录读取失败不得阻断其他共享目录。

### 9.3 指定文件夹映射

- 必须位于当前账号可见共享文件夹之内。
- 创建前确认目录存在且具备读取权限。
- 不允许与同一 NAS、同一账号下已有映射范围发生祖先或后代重叠。
- 远端根目录消失时暂停映射，不自动改指向同名新目录。

## 10. 只读保证

首版只向平台声明读取、枚举和内容获取能力：

- macOS 项目能力不包含创建、修改、重命名、删除或移动。
- Windows 占位文件使用只读属性和只读提供器策略；任何本地写入请求必须失败且不得产生待上传数据。
- 应用自己的映射管理页面不提供任何远端写操作入口。
- 只读失败提示说明“此云盘位置目前只能查看和下载文件”，不显示协议或权限实现术语。

实施原型必须验证常见应用不会通过另存、自动保存或元数据写入绕过只读限制。若平台无法可靠阻止某类写入，首版必须对对应文件或应用行为安全失败，不能静默生成无法同步的本地修改。

## 11. 元数据与文件内容加载

### 11.1 默认行为

- 创建映射时只获取根目录元数据。
- 用户展开目录时才枚举该目录。
- 列表可显示名称、类型、大小、修改时间和可用状态。
- 不预取文件正文、缩略图或媒体内容。
- “不加载文件”特指不下载文件正文；显示目录所需的元数据仍会按需读取。

### 11.2 打开文件

1. 系统请求文件内容。
2. 检查会话、网络、读取权限、远端版本和本地空间。
3. 将状态改为“正在下载”。
4. 读取文件内容并持续报告进度。
5. 完成后复核已写入大小。
6. 标记为临时可用。
7. 记录最后访问时间，用于临时缓存回收。

读取失败不得留下看似完整的文件。部分内容由平台允许时保留为可恢复状态，否则安全回滚为仅在线。

## 12. 手动离线保留

### 12.1 入口

- Finder 或资源管理器平台允许时提供上下文动作“始终保留在本机”。
- 应用文件浏览器提供相同操作。
- 映射管理页支持查看全部离线保留内容。

### 12.2 文件

- 必须先取得可信大小。
- 扣除已经本地可用的字节后计算新增占用。
- 空间检查通过后才进入下载队列。
- 用户取消后保留已完成且校验通过的文件，未完成项恢复为仅在线。

### 12.3 目录

- 递归枚举所有后代，显示“正在计算所需空间”，并提供取消。
- 大小未知、权限不完整或枚举未完成时禁用确认按钮。
- 枚举期间远端变化导致估算失效时，下载前再次检查。
- 目录固定状态只有在所有可读取后代完成后才显示“可离线使用”；部分失败时显示“部分内容不可用”并列出可恢复原因。

## 13. 磁盘空间校验

### 13.1 计算公式

```text
新增正文大小 = 选中项目未在本地存在的可信字节总和
临时峰值 = 当前实现可能同时占用的最大中转空间
安全余量 = max(2 GiB, min(卷总容量 × 5%, 20 GiB))
所需可用空间 = 新增正文大小 + 临时峰值 + 安全余量
```

临时峰值必须通过各平台原型测量后固化：

- macOS 首版保守按最大单文件缺失大小估算，避免 File Provider 交接内容时出现双份临时占用。
- Windows 根据 Cloud Files 内容传输是否直接写入占位文件的实测结果确定，验证前不得假设为零。

### 13.2 检查时机

- 用户确认离线保留前。
- 每个下载任务启动前。
- 大文件下载过程中按阈值变化检查。
- 缓存磁盘重新接入后。
- 临时缓存达到软上限准备接收新内容时。

### 13.3 空间不足

空间不足不得允许无保护继续。提示必须包含：

- 仍需空间。
- 当前可用空间。
- 差额。
- 当前缓存磁盘名称。
- “更换缓存磁盘”“减少选择内容”“管理缓存”操作。

建议中文文案：

> 本机缓存空间不足。缓存这些内容还需要 {required}，但“{volume}”只有 {available} 可用。请选择其他缓存磁盘，或减少要离线保留的内容。

建议英文文案：

> There isn’t enough local space. Keeping these items offline requires {required}, but only {available} is available on “{volume}”. Choose another cache disk or select fewer items.

空间属于易变化资源。通过开始前检查不代表后续一定成功，因此传输中仍须监控并在不足时安全停止。

## 14. 缓存策略与清理

### 14.1 两类缓存

| 类型 | 来源 | 自动清理 | 计入临时缓存上限 |
| --- | --- | --- | --- |
| 临时缓存 | 用户打开文件 | 是 | 是 |
| 离线保留 | 用户明确固定 | 否 | 否 |

### 14.2 默认临时缓存上限

- 新映射默认 10 GiB。
- 用户可选择 5、10、20、50 GiB 或自定义。
- 上限是软上限，不对正在打开的文件中途截断。
- 超限时只回收最久未使用、未固定、未打开、无错误且可从 NAS 重建的内容。
- 回收前后记录实际释放字节，不以文件逻辑大小冒充真实回收空间。

### 14.3 映射管理页

每个映射显示：

- 当前状态和上次成功检查时间。
- 缓存磁盘与可用空间。
- 离线保留占用。
- 临时缓存占用及上限。
- 可安全释放空间。
- 正在下载、失败和等待项目数。
- “在 Finder/资源管理器中显示”“暂停”“管理缓存”“移除映射”。

### 14.4 清理规则

- 清理临时缓存使用平台官方释放接口。
- 清理离线保留必须由用户主动选择并确认“释放本地空间”。
- 正在打开、下载、校验或状态不确定的文件不得清理。
- 首版不存在本地写入，因此没有待上传数据；未来加入写入时必须把待上传内容归为受保护数据。
- 清理失败时显示未释放项目数和重试入口，不把部分成功表述为全部完成。

## 15. 远端变化与刷新

### 15.1 首版刷新策略

- 用户打开目录时刷新该目录。
- 仅在线目录采用短期元数据缓存。
- 临时缓存和离线保留项目进入工作集周期检查。
- 应用从离线恢复、系统唤醒或 NAS 重新连接后触发检查。
- 用户可对映射或目录手动刷新。
- 后台失败采用指数退避并加入随机抖动，避免多个映射同时冲击 NAS。

### 15.2 一致性边界

File Station 当前公开适配没有经过验证的增量变更日志。首版必须：

- 显示“上次检查时间”。
- 不使用“实时同步”宣传。
- 远端删除或重命名按下一次刷新结果更新。
- 对本地已经打开的旧版本文件，不在应用使用期间强行替换。
- 远端版本在内容下载前变化时重新开始或返回“文件已更新，请重试”。

未来如需增量通知，必须按私有 API 发现规范单独建档、脱敏验证和兼容降级；内部能力缺失不得阻断按需读取。

## 16. 路径、名称与文件类型兼容

必须在平台适配层覆盖：

- Windows 保留名称、非法字符和尾随空格或句点。
- macOS 与 Windows 不同的大小写规则。
- Unicode NFC/NFD 规范化差异。
- 路径长度和单个名称长度。
- 同一目录下仅大小写不同的远端名称。
- 符号链接、硬链接、稀疏文件、设备文件和特殊套件目录。
- 文件名在本地转换后发生碰撞。

首版策略：

- 只支持普通文件和目录。
- 无法安全表示的项目显示为不可用项，附普通用户可理解的原因。
- 不静默改名后把修改写回 NAS。
- 如需显示经过转义的本地名称，必须保留稳定的远端身份映射，且在详情中展示原始名称。
- 路径、名称或冲突信息不得进入包含用户数据的诊断上传。

## 17. 会话、网络与后台运行

### 17.1 关闭窗口

- macOS：关闭最后一个窗口后应用保持运行；Dock 或菜单栏入口可重新打开窗口。
- Windows：拦截主窗口关闭，隐藏到通知区域，不在任务栏保留普通窗口。
- 第一次关闭时显示一次可关闭的说明，之后不反复打扰。
- “退出岚仓”是独立明确动作。

### 17.2 后台入口

菜单栏或托盘菜单至少包含：

- 打开岚仓
- 云盘位置总状态
- 暂停全部映射
- 继续全部映射
- 查看需要处理的问题
- 退出岚仓

菜单项必须同时提供中英文资源和屏幕阅读器名称，状态不能只依赖图标颜色。

### 17.3 显式退出

显式退出流程：

1. 停止接收新的缓存请求。
2. 等待正在提交给平台的关键回调到达安全点。
3. 将映射标记为暂停或提供器暂时不可用。
4. 持久化非秘密状态。
5. 退出进程。

只读首版不存在待上传修改，因此不需要写入冲突确认。退出后：

- 已完整缓存的文件应尽可能保持可读。
- 仅在线文件在提供器停止时显示暂时不可用。
- 下次启动自动恢复用户未手动暂停的映射。

macOS File Provider Extension 可能由系统独立拉起，因此显式退出需要通过共享状态让 Extension 返回“提供器暂时不可用”，不能仅关闭 SwiftUI 进程后假设扩展停止。

### 17.4 开机启动

- 存在启用映射时，创建向导建议开启“登录后启动岚仓”。
- 用户可以在设置中关闭。
- 关闭后明确提示：打开岚仓之前，仅在线文件可能不可用。
- 不绕过系统登录项权限或使用未公开自启动方式。

## 18. macOS 实现计划

### 18.1 新增组件

- Replicated File Provider Extension target。
- File Provider Item 与 Enumerator。
- 只读内容 Fetcher。
- Domain 注册和映射协调器。
- App 与 Extension 共享的非秘密映射状态。
- Extension 可访问、仅在存在映射时启用的最小安全会话桥接。
- 映射管理、创建向导和缓存管理 SwiftUI 页面。
- 菜单栏后台入口与窗口恢复逻辑。

### 18.2 预计需要的系统能力

- File Provider Extension 配置。
- App Group，用于共享映射状态和非秘密索引。
- Keychain Access Group，仅用于 Extension 获取存在映射的 NAS 会话；不得保存密码。
- 现有网络客户端权限。

这些能力会改变签名与权限配置，实施前必须单独审批。主 App 会话和可选密码继续保存在应用内 AES-GCM 加密存储。共享容器不得保存密码、OTP、SID、SynoToken、Cookie 或证书私钥；只有用户创建映射后，最小必要会话才进入共享钥匙串，最后一个映射移除、退出登录、会话失效或删除 NAS 时必须清理。

### 18.3 macOS 14 与 15 分支

- macOS 14：创建普通域，不展示缓存磁盘选择器。
- macOS 15+：选择磁盘后先调用系统资格检查；只有 `eligible` 才允许继续。
- 不合格原因转换为普通用户文案，例如磁盘只读、网络磁盘或当前不可用。
- 外置磁盘断开时域进入“缓存磁盘未连接”，不得在系统盘静默创建第二份同名映射。

## 19. Windows 实现计划

### 19.1 新增组件

- Cloud Files API 原生互操作层。
- Sync Root 注册、连接、断开和卸载协调器。
- Placeholder 创建、更新、固定、释放和状态报告。
- 文件内容读取和取消。
- 映射配置、安全状态和缓存统计。
- 通知区域图标、关闭拦截和窗口恢复。
- 映射创建与缓存管理 WinUI 页面。

### 19.2 原型优先项

1. 在临时开发目录注册单个本地模拟同步根。
2. 创建不含真实用户数据的占位目录和文件。
3. 验证打开文件触发内容回调。
4. 验证固定、释放、状态图标和资源管理器重启。
5. 验证只读限制。
6. 验证同步根断开、注销和卸载。
7. 验证 x64 与 arm64。
8. 验证未打包应用是否满足发布需求；若不满足，再提交打包或安装器变更方案审批。

### 19.3 Windows Repository 补齐

- 文件内容下载到受控目标或回调流。
- 可信大小和远端版本读取。
- 递归目录估算，支持分页、取消和部分失败。
- 下载进度、取消、会话恢复和最终大小校验。
- 与 macOS 对齐的错误分类和用户恢复动作。

## 20. 安全与隐私

- 映射、占位文件和平台身份只保存不透明 ID。
- 不把主机地址、账号、SID、SynoToken、Cookie、DID 或证书信息写入文件名、扩展属性、日志或系统状态说明。
- 本地缓存是用户可通过普通应用读取的文件内容，默认依赖 APFS 文件保护、FileVault、NTFS 权限和 BitLocker 等系统保护；界面应提醒共享电脑用户注意。
- 不宣称普通可浏览缓存经过应用级端到端加密。
- 每个 NAS 配置和账号的映射、索引、缓存统计与会话必须隔离。
- 删除 NAS 配置时，如果仍有关联映射，先阻止删除并引导移除映射。
- 桌面云盘诊断摘要仅输出 App 版本/build、系统版本/架构、生成时间，以及映射状态、
  暂停、缓存位置、缓存条目/字节和活动任务的聚合计数；不输出映射 ID、profile ID、
  domain/卷标识、显示名称、主机、URL、查询参数、路径、文件名、原始错误或会话材料。
- 缓存不进入应用自建云备份；平台是否备份由系统 File Provider 规则决定。

## 21. 移除映射

移除属于高影响本地操作，必须二次确认并说明结果：

1. 暂停映射并停止新请求。
2. 等待关键读取回调结束。
3. 统计已缓存内容和未完成任务。
4. 提供“取消”和“移除云盘位置”。
5. 平台支持时提供“先导出已下载文件”作为单独流程。
6. 注销 Domain 或 Sync Root。
7. 复查系统位置已移除。
8. 清理可再生索引和映射级状态。
9. 安全存储中仅在没有其他映射或功能使用时清理关联会话。

Windows 注销同步根可能将已完整下载的占位文件转换为普通文件，并永久删除未下载占位项。实施时必须按真实 API 行为验证，不能用普通目录删除替代注销流程。

## 22. UI 信息架构

### 22.1 主导航

在桌面端设置或文件模块中新增“云盘位置”，不新建与文件功能平行且重复的顶级产品模块。

页面层级：

```text
云盘位置
├── 映射列表
├── 创建云盘位置
├── 映射详情
│   ├── 状态
│   ├── 范围
│   ├── 缓存
│   └── 高级设置
└── 缓存内容管理
```

### 22.2 映射列表

每个映射卡片或列表行展示：

- 名称和 NAS 名称。
- “全部共享文件夹”或映射根文件夹。
- 状态图标与文字。
- 临时缓存与离线保留用量。
- 最近成功检查时间。
- 在系统文件管理器中显示的主要操作。

### 22.3 状态设计

- 使用平台原生图标：macOS 使用 SF Symbols，Windows 使用 Segoe Fluent Icons。
- 成功、等待、警告和错误必须同时有文字，不仅用绿、黄、红。
- 超过 300 毫秒的操作显示进度。
- 目录大小计算、下载和清理可取消。
- 错误紧邻相关映射或字段，并提供下一步操作。
- 动效只表达状态变化，时长控制在 150–300 毫秒，并支持降低动态效果。

界面以 SwiftUI、AppKit、WinUI 和 Fluent 原生规范为准，保持明确的状态反馈、键盘与焦点支持、错误恢复路径、可读对比度和降低动态效果支持。

## 23. 国际化与无障碍

### 23.1 本地化

- 所有标题、字段、按钮、状态、提示、通知、托盘菜单和无障碍文案同时提供英语与简体中文。
- 大小、日期、时间、数量和百分比按当前 App 语言格式化。
- NAS 名称和文件名保持原文。
- 不拼接完整句子；空间不足、项目数量和时间使用参数化资源。
- 翻译字符串不得参与状态判断或持久化。

### 23.2 无障碍

- macOS 支持完整键盘访问、VoiceOver、动态文字和降低动态效果。
- Windows 支持键盘导航、Narrator、高对比度和文本缩放。
- 焦点顺序与视觉顺序一致。
- 图标按钮具有可访问名称和提示。
- 进度变化使用非抢焦点的系统可访问通知。
- 错误、空间不足和会话过期必须被屏幕阅读器读出。
- 深色和浅色模式分别验证正文 4.5:1、非文本状态图标 3:1 的最低对比度。

## 24. 错误与恢复

| 场景 | 用户状态 | 恢复动作 |
| --- | --- | --- |
| NAS 离线 | NAS 当前不可连接 | 重试、检查连接 |
| 会话失效 | 需要重新登录 | 重新登录 |
| 无读取权限 | 无法访问此内容 | 返回上级、刷新权限 |
| 文件已变化 | 文件已更新 | 重新打开 |
| 本地空间不足 | 缓存空间不足 | 更换磁盘、减少选择、管理缓存 |
| 缓存磁盘断开 | 缓存磁盘未连接 | 重新连接磁盘、改用其他位置 |
| 本机运行状态无法读取 | 本机状态需要恢复 | 重新连接；不修改 NAS 文件 |
| 目录估算不完整 | 无法计算完整大小 | 重试、查看不可访问项目 |
| 路径不兼容 | 此项目无法在本机显示 | 查看原始名称说明 |
| 提供器暂停 | 云盘位置已暂停 | 继续 |
| 系统能力不可用 | 无法创建云盘位置 | 查看系统要求 |

所有错误必须说明发生了什么和用户下一步可以怎么做。技术错误码只进入受控高级详情或脱敏日志。

## 25. 测试计划

### 25.1 领域单元测试

- 映射范围重叠判断。
- 全部共享文件夹与单目录范围转换。

## 26. 分阶段实施与出口

### D0：契约与风险原型

交付：

- 映射、项目、状态、缓存和错误领域契约草案。
- 五端影响评估；iPhone、iPad、Android 标记为不实现系统映射但共享契约不应破坏。
- macOS File Provider 最小本地数据原型。
- Windows Cloud Files 最小本地数据原型。
- 只读写入阻止、注册与卸载行为报告。

出口：

- 两端都能在系统文件管理器显示本地模拟占位树。
- 打开模拟文件能够按需提供内容。
- 写入被可靠拒绝。
- 卸载不会误删原型范围外文件。
- 所需权限、打包和持久化变更已经审批。

### D1：共享领域与只读 Repository

交付：

- 映射领域模型和状态机。
- 映射配置存储。
- Windows 文件内容读取与目录大小估算。
- 统一错误、空间决策和脱敏诊断。

出口：

- 单元测试通过。
- 两端对同一脱敏 fixture 产生一致的文件树、大小和状态。
- 不引入内部 API。

### D2：macOS 只读云盘位置

交付：

- File Provider Extension。
- 全部共享文件夹和指定文件夹映射。
- 按需读取、状态、暂停与恢复。
- macOS 14 默认缓存位置。
- 窗口关闭后台运行和菜单栏入口。

出口：

- Finder 端到端读取通过。
- 重启、休眠、离线和重新登录通过。
- 无写入口和远端副作用。

### D3：Windows 只读云盘位置

交付：

- Cloud Files Adapter。
- Sync Root 生命周期。
- 按需读取、状态、暂停与恢复。
- 托盘、关闭拦截和窗口恢复。

出口：

- Windows 10 2004 与受支持 Windows 11 设备验收。
- x64 和 arm64 构建通过。
- 资源管理器重启和应用升级恢复通过。

### D4：离线保留与空间保护

交付：

- 文件和目录离线保留。
- 递归大小估算。
- 空间公式和下载中监控。
- 空间不足恢复流程。
- 缓存任务进度、取消和失败重试。

出口：

- 不足空间不会开始或破坏已有缓存。
- 目录部分失败准确呈现。
- 缓存前、缓存中和完成后的字节统计可复核。

### D5：缓存管理与外部磁盘

交付：

- 映射级临时缓存上限和 LRU 回收。
- 离线保留与临时缓存分项统计。
- macOS 15+ 合格外部磁盘。
- Windows 经原型验证支持的缓存磁盘范围。

出口：

- 清理只释放本地可重建内容。
- 外部磁盘断开不产生第二份隐式映射。
- 真实释放空间与界面统计误差在定义阈值内。

### D6：发布验收

交付：

- 中英文资源完整性。

出口：

- 本地化完整性与硬编码扫描通过。
- 目标平台构建、自动化和实机测试通过。
- 无秘密、真实用户数据或一次性调试生成物。
- 所有“未验证”项得到结论或明确降级关闭。

## 28. 关键风险与处置

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 无公开增量变化源 | 远端变化非实时 | 访问时刷新、工作集轮询、显示上次检查 |
| 路径不能提供稳定文件 ID | 远端重命名丢失本地状态 | 首版按删除与新增处理，继续验证公开字段 |
| Windows 未打包发布限制 | 安装和 Shell 集成不稳定 | D0 原型验证，必要时提交打包方案审批 |
| macOS 14 不支持外部域 | 无法更换缓存磁盘 | macOS 14 使用系统盘，macOS 15+开放 |
| 大目录估算耗时 | 缓存确认等待较长 | 分页、进度、取消、禁止未知大小继续 |
| 缓存过程中空间被其他应用占用 | 下载失败或系统盘过低 | 安全余量、过程监控、安全停止 |
| 应用退出后系统仍拉起 Extension | 用户预期与实际不符 | 共享暂停标志，Extension 返回暂时不可用 |
| 只读被应用自动保存绕过 | 产生无法同步的本地修改 | 平台能力最小化、只读属性、集成测试、安全失败 |
| 外部磁盘突然拔出 | 映射不可用或状态损坏 | 卷身份校验、断开状态、重接恢复、不自动迁移 |

## 29. 首版验收标准

只有同时满足以下条件，首版才算完成：

1. 用户可创建“全部共享文件夹”和“指定文件夹”两种只读云盘位置。
2. 创建映射不会下载任何文件正文。
3. Finder 和文件资源管理器可按需浏览目录并打开文件。
4. 用户可固定文件或目录离线使用。
5. 缓存前完成可信大小和实际缓存磁盘空间检查。
6. 空间不足不会启动缓存，并提供三个明确恢复入口。
7. 应用可按映射显示离线保留、临时缓存和可释放空间。
8. 清理缓存不会删除或修改 NAS 文件。
9. 所有写入、重命名、移动和删除请求安全失败。
10. 关闭窗口后应用保持后台运行；显式退出后停止新的在线读取。
11. 网络、会话、磁盘和系统重启后的状态可恢复且不误报。
12. 英语、简体中文、深色模式、键盘和屏幕阅读器验收通过。
13. macOS 14 使用系统默认缓存位置；macOS 15+ 只允许合格外部磁盘。
14. Windows 支持范围经过目标设备实机验证，不以文档阅读替代验收。
15. 不新增或泄露秘密、真实用户路径、主机和未脱敏响应。

## 30. 后续只读之外的演进

只读首版稳定后，若要支持读写，必须另立计划，至少新增：

- 本地修改队列和断电恢复。
- 写前权限和远端版本检查。
- 原子上传与结果回读。
- 删除确认、回收站和恢复。
- 离线写入和冲突副本。
- 重命名、移动与大小写冲突策略。
- 多端同时修改测试。
- 待上传数据保护和退出阻止。

这些能力不能通过简单开放写权限完成，也不能沿用只读缓存的清理规则。
