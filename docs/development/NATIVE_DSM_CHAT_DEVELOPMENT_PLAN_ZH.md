# Synology Chat 原生功能与后续计划

本页维护当前功能、平台差异和剩余工作。内部用户聊天请求以[Chat API 参考](../api/reference/chat.md)及[端点记录](../api/discovery/endpoints/chat-advanced-actions.md)为准；历史实现、测试数量和修复经过集中在[macOS 反馈历史](../archive/2026-h2/MACOS_FEEDBACK_HISTORY.md)、[移动实施历史](../archive/2026-h2/APPLE_MOBILE_IMPLEMENTATION_HISTORY.md)和[验证历史](../archive/2026-h2/RELEASE_VALIDATION_HISTORY.md)。不再把已经交付的语音、搜索或投票参与列为待开发。

| 用户结果 | macOS | iPhone / iPad | 其他平台 |
| --- | --- | --- | --- |
| 普通单聊与私人群聊 | 用户列表、会话、文字、分页、成员与建群已接入 | 已接原生表单与分步建群恢复 | Windows/Android 按各自实现与平台矩阵记录，不由 Apple 结果推定 |
| 搜索、编辑与线程 | 关键词搜索、本人编辑、文字线程回复已接入 | 全局/当前聊天搜索、原消息定位、编辑、完整线程分页与回复已接入 | 后续 Mac 增量需逐项对齐 |
| 附件与语音 | 图片/文件/媒体读取、单附件、AAC 录音/试听/播放/发送 | 系统选择器、单附件、一击播放/暂停、主动录音/试听/发送 | 语音在 Windows/Android 仍属后续范围 |
| 提醒、文字定时与投票 | 创建/管理提醒、定时文字、创建及参与单选/多选投票 | 已接创建/参与/结果/结束状态，提醒和定时管理及持久恢复 | Windows 已有提醒、纯文字定时与无附件投票；Android 请求差异单独修正 |
| 公告、转发、删除与关闭 | 查看/设置公告、批量转发、本人删除、关闭会话已接入 | 原内容预览、多接收人转发、按项恢复与具体后果确认 | 权限及恢复语义按各端实际实现核对 |
| 实时与阅读同步 | 订阅绑定已连接且启用 Chat 的工作区；页面隐藏不停止，断开/退出/关闭模块清理 | 前台整个工作区单一订阅、低频补读、实际可见位置同步与历史位置保留 | Windows 已接 EIO 4/3 与同源证书管线；不等同真机或真实 NAS 验证 |
| 通知 | 桌面新消息通知与可控授权入口 | 主动开启的本地到期提醒，最近 50 条未来提醒；不保存正文/附件/凭据 | 远程推送需要单独服务、权限与产品范围 |
| 加密会话与实时通话 | 尚未形成可用实现，加密收发保持关闭 | 当前非目标 | 各端不得把普通会话协议当作加密支持 |

群聊是私人多人会话，不包括公开频道、组织或服务器管理。单个/批量关闭会话不等于删除聊天历史；本人删除还须满足服务器策略和当前作者身份。单附件支持不代表多附件发送已经实现。

## 业务与安全不变量

- 使用内部 `SYNO.Chat.*` 用户会话；公开 Bot/Webhook 的 `SYNO.Chat.External` 不能替代普通账号权限。方法版本、JSON 结构和恢复字段只在 API 参考与端点记录维护，不在计划中复制伪代码或猜测请求。
- 显示名称不作为本人身份；使用稳定用户/消息/会话标识。删除与编辑先回读原对象、作者、内容和权限，完整分页缺失才可形成相应结果；坏列表不当空列表。
- 发送区分草稿、已提交、已确认和未知。缺少回执不得凭相同文字、同名会话、近似时间或相似条目认领；未知不自动重发，普通刷新不释放防重复保护。
- 转发按原内容、目标会话、成功回执及唯一新增结果确认；部分完成只处理剩余目标。建群按创建、加入与邀请记录，缺创建编号不按同名认领，已完成步骤不重复。
- 移动发送、建群、编辑/删除/转发、投票/提醒/定时及公告/关闭保留独立、受保护的恢复记录。提交前保存失败不写；账号改变后的回调归原账号，互斥覆盖相互冲突的操作。macOS 旧调用兼容不等于具备移动持久队列。
- 附件只从已授权的来源读取，会话不进入 URL；恶意外链、错误 JSON 或跨来源重定向不能被当作媒体。录音和媒体副本受系统文件保护并排除备份，结束后清理。
- 阅读位置来自实际可见消息，不以页面打开当全部已读，不覆盖其他客户端更晚位置。实时事件只触发可信回读；订阅代次、低频校准和取消由唯一所有者管理。
- 麦克风权限由主动录音触发；后台、来电或音频中断不自动恢复录音。iPad 按实际剩余宽度与动态文字切换布局，保留所选会话。
- UI 只表达消息、保存、发送或恢复状态；内部结果类别不得成为默认提示。中英文、浅深色、触控、键盘、屏幕阅读器和降低动态效果一并验证。

## 后续工作顺序

1. 先处理当前客户端的可复现反馈，包括真实投票规则、阅读同步、通知、媒体互播与中断恢复；完整云端和设备结论按各端证据分别记录。
2. Windows/Android 对照[平台矩阵](../progress/PLATFORM_MATRIX.md)与各自计划开展增量，不因共享协议增加方法自动开放入口。Android 已知投票参数差异属于独立修正，不能写成兼容通过。
3. 加密聊天只有在官方客户端行为、加解密协议、密钥保管/清理和失败恢复具备证据后，才能单独立项；禁止静默降级明文，不复用普通发送按钮假装支持。
4. 多附件、实时通话、公开频道管理与远程推送需单独确定目标平台、协议和授权。当前非目标不写成仅待设备验收。

## 验证与验收

共享网络与领域测试验证参数、分页、作者/权限、回执、断线未知、重复提交、账号切换和迟到响应；平台行为测试覆盖输入、消息定位、媒体生命周期、布局及通知。实际 iPhone/iPad UI 各自运行，Mac 共享改动另做回归。静态断言、合成网络、构建与真实套件行为分别记录。

| PENDING_USER_VALIDATION 前置条件 | 操作与预期 | 脱敏反馈与影响 |
| --- | --- | --- |

| 测试投票、提醒和定时对象 | 单选/多选/匿名/截止，跨客户端读取，取消与发送时间边界；未知只读取原对象 | 是否重复、原对象是否保留及错误类别；真实参与规则和时间行为待验 |
