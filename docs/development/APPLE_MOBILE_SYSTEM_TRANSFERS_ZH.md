# M8 系统传输、分享与 Files 实施账本

当前总状态：M8a 普通文件后台与 M8b 系统分享已完成源码和本机两端验收，
照片、跨 NAS 与 Office 后台的后续接入见[执行器账本](APPLE_MOBILE_BACKGROUND_EXECUTORS_ZH.md)。
M8c Files 已实现共享运行时与移动读写，默认只读目录仍有可复现系统元数据失败，
见[Files 账本](APPLE_MOBILE_FILES_PROVIDER_ZH.md)；完整移动云端也仍在复验。
下文按各切片实施时点保留原始基线和决策，其中的“后续”不替代上述当前结论。

本片属于已批准的 M6–M8 目标，沿用 2026-10-06 用户离线自主决策授权。开始时
main 为 `bd285f41`；独立云端 UI 修正完成本机验收后以 `539de49f` 推送，完整云端检查仍在运行。当前负责人
单一修改移动传输执行、必要系统桥接、工程配置、双语资源及正式测试；共享 `FileUploadBatch.pause()` 仅增加暂停尚未开始批次的能力，避免系统到期后继续发送后项，macOS 执行回归。不修改
Windows/Android，不自动写入真实 NAS 数据，不发布或改变主 App 身份。

## 对齐范围与技术决策

| macOS 证据 | 两端用户结果与交互转换 | 契约、安全与当前等级 |
| --- | --- | --- |
| `WorkspaceModel` 文件下载与 `FileUploadBatch` 上传语义；移动现有 `MobileTransferCoordinator`、`MobileFileUploadQueue` | 用户开始文件下载/上传后可切换 App；系统允许时继续传输、显示真实进度并支持取消；系统中断后回到现有任务恢复 | 保持既有 File Station 下载/上传、权限、原账号、证书与同源保护；实现前基线仅有进程内任务，无系统持续后台能力 |
| Mac 常驻进程与移动持久队列 | iOS/iPadOS 26 使用系统持续后台任务；17–25 或系统不接受持续任务时使用有限后台时间，超时暂停/停止并保留恢复信息 | 最低版本仍为 17；用户强制退出或系统终止不承诺继续，未知上传只读恢复，不自动重放 |

原主计划中的 Background URLSession 需要调整：Apple 明确说明其后台请求自动跟随
重定向，无法调用应用的拒绝重定向回调；当前 NAS 下载使用 Cookie 与
X-SYNO-TOKEN，上传还包含正文认证。直接替换会失去现有同源拦截，不能仅以提前
请求一次未发生重定向证明以后安全。保留当前网络传输与证书实现，改用系统
`BGContinuedProcessingTask` 为用户主动发起的传输提供执行时间；它支持网络，
系统提供进度和取消。此决策没有更换 API、认证或放宽连接保护。

依据：[Apple 持续后台任务](https://developer.apple.com/documentation/backgroundtasks/performing-long-running-tasks-on-ios-and-ipados)、
[后台重定向限制](https://developer.apple.com/documentation/foundation/urlsessiontaskdelegate/urlsession(_:task:willperformhttpredirection:newrequest:completionhandler:))。
当前 SDK 的 `BGTaskRequest.h` 明确默认资源包含 CPU/网络，接口从 iOS 26 可用；
不申请后台 GPU 权限。持续任务使用即时执行策略，系统拒绝时按有限后台能力降级，
不排队等待系统日后重新发起写操作。

## 配置影响、恢复与回滚

- 主 App 增加本 App 前缀的后台任务标识声明和必要的 processing 模式；保持最低版本、
  Bundle ID、签名方式和网络权限。无新增第三方依赖，扩展身份与共享权限属于后续片。
- 后台资格仅绑定当前执行身份；结束、取消、账号切换与迟到系统回调不得把资格授予
  新任务。上传/下载继续使用现有持久队列，不另建第二套上传或认证实现。
- 继续保留本机副本完整文件保护与排除备份。锁屏导致文件不可读时保留可恢复状态，
  不为后台便利降低文件保护；未接入后台的其他能力不显示持续执行承诺。
- 系统取消和时间到期须取消对应网络操作；已提交上传不能因取消被记为未提交，
  也不能自动重传。进度必须源自真实传输，不用定时增加百分比维持系统资格。
- 回滚移除新增后台桥接与配置，沿原前台执行和持久恢复。没有登录数据迁移，也不
  自动清理未结束的任务或副本。正式分享扩展和 Files 的配置将在各自实施前列明。

## 独立集成与只读对抗复核（2026-10-07）

在实现之外另行复核系统回调与网络状态：每次执行的系统标识独立，结束后迟到授予会立即归还；已取得持续资格后忽略旧有限时间的迟到到期回调。到期先取消网络、保存恢复阶段，再结束系统资格。下载请求仍由原 `MobileTransferCoordinator` 管理；上传批次沿用原副本、目录顺序、提交前保存及逐项回读，不从系统回调新建请求。

上传到期会暂停当前和同账号未开始批次，避免 `onSettled` 继续写入；提交中的项目保留原 `needsReconciliation`，恢复时须读原目标，未提交项等待用户继续。切换账号先取消旧批次，旧后台身份不得影响新账号；未知上传不因新系统资格自动重放。没有改变文件保护、同源拦截、证书验证和持久格式；仅最终校验成功才把系统进度标为完成。实际系统拒绝持续执行仍走有限时间，17–25 不调用 26 专属 API；进程终止后不承诺继续执行或字节续传。该复核由当前负责人另行执行，不冒称其他模型审查或真实 NAS 结果。

## M8b 分享扩展与最小账号共享

本片基线为 `dd874163`，沿用上述用户自主决策授权。当前负责人单一修改移动组合根、
登录生命周期、扩展共享支持、工程/权限配置、语言资源、分享界面、任务恢复及对应测试。
macOS `FileUploadPlan`/`FileUploadBatch` 为上传顺序、重名、未知结果和回读的语义依据；
iPhone/iPad 均采用系统分享面板内选择已登录 NAS 与文件夹、明确上传、逐项结果与取消。
原任务未得到结果时只读取恢复，不能因系统重复回调或进程重启重新提交。

必要配置与回滚：主 App 身份及最低版本不变；新增后缀 `.share` 的分享扩展，以及后续
`.files` 的 File Provider 扩展。两扩展与主 App 共用移动专属
`group.io.github.qwertyuiop1995.dsmnativeclient.mobile` 容器及
`$(AppIdentifierPrefix)io.github.qwertyuiop1995.dsmnativeclient.mobile.shared` 会话组，
不会使用 macOS 容器。正式签名需团队为这些目标配置对应权限；本机模拟器不代替该验收。
只共享必要连接快照、短期会话和用户主动提交的文件；密码与原登录存储保持私有。
会话沿用现有 `AfterFirstUnlockThisDeviceOnly` 保护，文件/快照采用完整文件保护并排除备份。
独立记录不迁移旧开发数据；回滚移除扩展嵌入与共享发布，保留未完成副本供用户恢复，
主 App 原上传和登录不依赖扩展可用性。无新增依赖或私有 NAS 接口。

账号发布使用独立会话编号，元数据先预留、凭据保存成功后才激活；退出、删除与身份变化
先撤销可见记录，再清理共享会话。扩展每次请求重新检查原发布身份与会话是否有效；
进行中的操作接到撤销后取消，保留已提交的未知结果，不把本机取消当成 NAS 回滚。
共享记录在进程间互斥读写，不用缓存或最后写入覆盖掩盖两个扩展的并发变化。

Apple 的 `NSExtensionContext.open` 不支持普通 Share 扩展主动打开主 App，因此不采用
响应链或私有方法强行跳转。扩展内完成可用的选择与上传主流程；关闭或系统中断后，
主 App 提供同一任务的后续恢复。依据：[Apple 扩展打开 URL 的适用范围](https://developer.apple.com/documentation/foundation/nsextensioncontext/open(_:completionhandler:))。
已形成扩展接收、选择目录、明确上传、完成与取消、主 App 继续或只读恢复的主流程。
Files 域、读写与冲突仍是后续独立实现。

### 集成审查与只读对抗复核

当前负责人在实现之外独立复核：主 App 私有 Keychain 组仍列在首位，共享组只保存
独立编号的会话；密码、DID 和其他套件能力没有进入共享快照。发布先预留、保存并
清理旧会话，最后激活；取消、换账号和迟到保存均不能接管新发布。启动时撤销未完成
或已经不存在的本地账号发布，普通显示名称修改不改变账号身份。清理失败保留编号
重试，可见账号撤销不等待清理完成。共享目录与快照损坏时停止访问，不覆盖损坏记录。

扩展每次请求前后检查原发布身份，进行中撤销会取消网络；继续沿用证书和同源拦截。
附件在系统回调内协调读取并冻结，拒绝越界文件名与根符号链接。队列原提交前落盘、
未知上传回读及重名保护保持不变；替换仍须具体风险确认。每个分享记录由独立文件锁
保护，关闭等待网络结算及记录保存后才释放；主 App 不在扩展仍占有时创建第二个上传。
恢复同时检查 manifest 与队列账号，身份不符的记录不能被当成空记录清理。这是源码、
合成自动化及模拟器复核，不冒称真实 NAS 或其他模型的独立结论。
