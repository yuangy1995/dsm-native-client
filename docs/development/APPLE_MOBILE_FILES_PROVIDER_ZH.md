# M8c Files 接入实施账本

本片属于用户已批准的 M6–M8 目标及离线自主决策范围，依赖 M8b 的移动专用共享
账号、会话撤销和文件保护。M8b 已在 `dc2f2fb0` 完成。共享提取、移动位置管理和
系统读写已实现；本机默认只读系统流程仍有可复现失败，原因尚未确认，不能宣告本片完整验收。

## 事实基线与范围

| macOS 证据 | iPhone/iPad 等价用户结果 | 依赖、安全与当前等级 |
| --- | --- | --- |
| `dc2f2fb0` 的 `apple/Apps/DsmMac/FileProviderExtension/ProviderRuntime.swift`、`ProviderItem.swift`、`ProviderEnumerator.swift`（现提取到 `apple/Packages/DsmFileProviderRuntime/Sources`） | 在系统“文件”中查看同一 NAS 目录，按需下载、使用本机缓存、保留稳定文件身份与同步锚点 | 复用公开 File Station List/Download/GetInfo；版本与大小校验、容量限制、账号/路径隔离。共享和移动聚焦自动化通过，两端系统读写流程通过 |
| 同目录 `FileProviderExtension.swift`、`ProviderOperationRegistry.swift`、`ProviderErrorMapper.swift` | 系统原生取消、错误与重试，不复制 Finder 外壳或桌面菜单 | 当前 Mac 的平台桥接需要提取共享行为并保留独立平台入口；现有 SPM `DsmFileProviderRuntime` 测试是回归依据 |
| `DesktopDriveWriteback.swift` 与 `ProviderRuntime.writeItem/deleteItem` | 在其他 App 编辑后写回、遇到版本冲突停止覆盖，支持创建、改名、移动与明确删除 | 复用既有写前检查、稳定副本、持久恢复、写互斥与结果回读；新增系统入口属于数据写/删除高风险。编辑、删除分别主动授权；合成自动化及系统编辑回传通过，真实 NAS 待验 |
| `MobileExtensionAccounts`、`MobileExtensionTransport` | 用户主动为已登录连接启用 Files；退出或换账号后不能继续请求原 NAS，更不能接管新账号 | 原始账号身份与系统映射绑定，不能只比较 profile UUID；已实现的 M8b 会话桥接作为依赖 |

当前负责人单一修改共享 File Provider 实现、两端薄入口、移动位置管理、工程配置、
双语资源与测试。允许必要 Mac 引用调整，保持已发布 Mac 的数据格式和业务行为，
并执行完整共享测试、Mac 双架构构建与移动两端验证。不修改 Windows/Android。

## 已核实的平台差异

- 当前 SDK 的 `NSFileProviderReplicatedExtension`、临时目录、下载副本清理、
  `waitForChanges` 与 `waitForStabilization` 支持 iOS 16，最低版本继续保持 17。
- `NSFileProviderDomain.userInfo`、外接卷、隐藏位置与管理器的 disconnect/reconnect
  是 macOS 专有 API，不能用 iOS 版本判断冒充支持。移动域使用稳定标识关联自己的映射记录。
- `supportsSyncingTrash` 在 iOS 18 才可设置；17 的行为必须按实际项目能力和回调核对。
  不能把 Mac 的赋值直接移植，也不能把移动端“最近删除”假装成 NAS 回收站。
- iOS 没有 `preserveDirtyUserData`/`preserveDownloadedUserData` 两种域移除模式。
  因此退出账号和暂停位置不能自动删除系统域或本机副本。若提供移除位置，须先检查
  可观察的未完成写回与系统同步结果，并明确说明本机副本/未保存改动的后果；不得承诺
  Mac 独有的保留模式。NAS 中文件的删除仍是独立的系统文件操作。

依据为本机 Xcode 26.5 SDK `FileProvider.framework/Headers/NSFileProviderDefines.h`、
`NSFileProviderDomain.h` 与 `NSFileProviderManager.h` 的声明及可用性；相关在线说明见
[Apple File Provider](https://developer.apple.com/documentation/fileprovider)。这些可用性证据
不等于真实设备已通过注册或写回测试。

## 必要配置、数据与回滚

新增 `.mobile.files` 扩展，复用 M8b 的移动 App Group 和共享会话组，主 App 身份、
最低系统版本、密码存储、NAS API 与第三方依赖不变。正式签名需为该新目标配置同组权限。
将可复用 File Provider 行为提取到现有 Apple Package 的独立模块，Mac 保留原 principal
class 和平台默认依赖，移动注入账号、受保护存储与系统适配；不能维护第二份写回算法。

移动映射记录独立保存原账号身份、NAS 范围及系统域编号，复用既有映射/路径/写回存储
处理业务状态。重新登录可使用同一身份的新会话；更换账号、地址或信任边界时旧位置
停止远端访问并保留恢复资料。系统回调必须重新验证当前绑定，不能根据过期的 UI 选择写入。
原 Mac 存储不迁移；移动端按当前开发格式实现，不维护旧开发数据兼容分支。

回滚停用新增移动入口和扩展嵌入，保留尚未结束的任务与副本供恢复；不得通过自动移除
域完成回滚而静默删除用户编辑。Mac 可回退到提取前引用，其持久格式与域身份应始终相同。

## 实施顺序与验收

1. 提取共享运行时与系统回调；保持 Mac 行为，编译核对 iOS 17 与现有 SDK 的实际可用性。
2. 实现原账号绑定、域注册/列表/暂停及读取、按需下载和缓存。根项目不依赖网络显示，
   真实读取仍须检查账号、权限和会话；验证进程重启、迟到回调与取消。
3. 接入创建、编辑写回、改名、移动、冲突与删除。沿用原副本、版本、权限、互斥与
   未知结果恢复；分别处理系统操作与主 App 的账号/位置生命周期。
4. 单独执行集成审查和只读对抗复核，运行共享/Mac 回归，以及两种模拟器的行为与
   实际系统入口测试。真实调度、设备文件保护、正式权限和 NAS 测试再列具体的
   `PENDING_USER_VALIDATION` 条件，不能以缺少设备中止其他源码工作。

非目标：Finder 菜单、外接卷迁移、桌面登录项、多窗口与未经平台支持的常驻运行。
iPhone 和 iPad 的业务范围相同，位置管理与确认采用各自原生布局。

## 当前实现进展（仍在验证）

- 原 Mac 运行时、枚举、系统回调和错误映射移到
  `apple/Packages/DsmFileProviderRuntime/Sources`；两份原聚焦测试移到该模块的
  `Tests`，并同时加入移动测试目标。Mac principal class、Bundle ID 和数据格式保持。
  共享库最终 74 项聚焦通过，包含指定版本变化零下载、实际配置类型与协议调用一致；
  完整共享 3103 项 XCTest（172 项既有跳过）及 12 项 Swift Testing 通过。
- `DsmFiles` 为独立 iOS 扩展，复用移动专属 App Group 与短期会话。每个位置保存
  原账号身份、地址、证书信任和独立 UUID；同身份重登换共享会话编号不会换域，
  更换身份或证书不会接管旧位置。每次传输与在途观察都重新检查绑定及撤销。
- 主 App 已接添加、暂停/恢复、编辑/删除独立授权、待完成修改、明确覆盖/删除重试、
  副本导出和停止操作。移除先等待系统、拒绝未完成记录，再停止远端访问并移除域；
  失败保留暂停，允许明确恢复。移除不自动删除恢复目录。未被用户启用的新位置不等待
  尚不能进行的系统同步；原账号/信任失效时仍能保存本机副本并明确移除旧位置。
  两端系统浏览、原位下载与编辑回传已通过；真实 NAS 和设备生命周期仍需验收。
- iOS 的单位置临时缓存上限设置为 512 MiB，系统管理实际已下载副本。SDK 的
  `contentPolicy.downloadEagerlyAndKeepDownloaded/downloadLazily` 与
  `versionNoLongerAvailable` 为 Mac 专有；移动不暴露永久固定下载承诺，指定旧版本
  已变化时返回可用的同步错误并保持零下载。移动通过 `allowsEvicting` 明确允许
  系统回收已上传、未编辑且未占用的副本，不把永久不可回收的默认值当作缓存策略。
  Mac 原 contentPolicy 行为保留。
- 共享配置的显式目录初始化与写回副本，在 iOS 使用完整文件保护和排除备份；
  Mac 仍使用原沙盒与目录权限。移动错误文案指向当前“系统文件”设置，不能引用
  “这台 Mac”或桌面读写窗口。枚举错误统一经过已有错误映射，符合系统错误域要求。
- `MobileFilesProviderTests` 覆盖账号绑定、原会话撤销、暂停、损坏记录、真实资料仓库
  读写/删除、冲突副本与域生命周期。另新增真正系统文档选择器、原位读写与独立
  扩展的合成 UI 测试；测试 NAS 使用 `.invalid` 域名和独立目录，不请求真实 NAS。

中间构建已暴露并修正 iOS 不可用缓存策略/版本错误，以及共享回调的 Objective-C
方法导出；一次测试构建遇到新增调试入口尚未加入生成工程，已重新生成。
两端最终 22 项移动位置测试通过，74 项共享运行时测试也已在两种模拟器通过。

## 独立集成与只读对抗复核

当前负责人在实现之外复核原 Mac 与提取后的差异、两端组合根和恢复流程：Mac
保留原 principal class、域身份、存储格式和默认依赖；共享枚举、缓存与写回算法只保留
一份。曾发现公开协议的默认异步实现遮蔽具体 actor 的状态方法，使移动请求被错误拒绝；
已移除该默认实现，在只读测试替身中显式拒绝，并补实际类型/协议两条调用路径回归。

每个系统域绑定原账号身份、NAS 范围与证书信任。每次请求前后及在途观察均检查
原绑定、共享会话、暂停与配置损坏，不能用旧缓存继续访问。退出和信任变化只撤销
远端访问，不自动删除系统副本。编辑与删除分别确认，冲突不自动覆盖，未知结果不
自动重发；恢复操作持有同一映射的写互斥。停止有内容的修改须先由系统导出成功，
取消导出不算成功；系统移除先拒绝未完成记录，再关闭远端访问、移除及回读结果。

系统位置必须由用户启用，生产代码没有设置测试自动启用模式。模拟器首次浏览时，
系统可能已显示位置开关为开，但域仍未启用并提示打开 App；通过“编辑位置”关闭再
开启该测试提供器后，两端均完成真实读取与写回。正式测试明确覆盖这个系统操作，
没有使用私有方法或放宽系统权限。

Mac 最终 Release 主 App 与 File Provider 已构建通过并确认 x86_64/arm64，未安装
或启动成品。复核由当前负责人独立进行，没有调用另一模型，没有真实 NAS 写入。

## 未解决：默认只读系统目录（2026-10-07）

本机为 arm64、macOS 27.2（26B5091g），使用 Xcode 26.5 与 iOS 26.5（23F77）
模拟器。正式 `test默认只读位置通过系统文件下载` 在 iPhone/iPad 均复现：域已由
系统界面启用，扩展枚举返回合成 Shared 目录，但系统本地目录创建失败，Files 显示空内容。
`fileproviderctl dump` 中原测试域的目录任务报告 POSIX 1，以及
`libfssync.DocumentWharfError.cannotCreate / VFSFileError.cannotSetMetadata`，系统开始退避。
同一实现主动允许编辑后已完成两端浏览、下载和上传；这只是对照证据，不能据此要求
用户授予写权限才能读取，也不能证明真实设备必然通过。

已分别尝试不发布目录大小、显式对齐只读文件系统标志、仅允许文件回收，单个 iPad
用例均仍失败。这三项尝试全部撤回，不保留未证明的兼容分支，不扩大读取/编辑权限。
失败用例与原断言保留，没有删除、跳过或改成预期成功。当前只能确认系统落盘阶段
失败，尚未确认是产品元数据适配还是本机系统问题；需继续对照云端模拟器及正式签名
真机，不能把该缺口当作已完成验收或冒称 Apple 已确认的 iOS 缺陷。

这一问题不阻塞独立的 M8 照片、跨 NAS 与 Office 后台源码工作；完整收口仍须明确
记录其最终结论及可用范围。

后台功能整合后再次以本机临时签名运行同一 iPhone 用例，仍在 62.972 秒失败；系统日志
再次显示枚举已返回 1 个目录，随后 `create-item` 设置元数据得到相同 POSIX 1。
中间一次误用无签名构建，在合成环境初始化共享容器/会话时提前崩溃；恢复项目既定
`CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-` 后不再出现该启动崩溃。云端现有构建
已使用正确临时签名，不需变更生产权限。后一次结果包为
`build/m8d-readonly-signed-phone.xcresult`；只读目录问题与该中间构建错误分别记录。
