# 移动 Files 接入与验收

M8c 已实现系统位置注册、浏览、下载、缓存、原位编辑、冲突与删除恢复。M8ab 改为 iOS 非复制式适配，macOS 保留复制式入口，共用 `DsmFileProviderRuntime` 的业务与安全逻辑。

两端正式 App 的默认只读、编辑回传和中文权限流程均有本机通过证据。`5019da83` 云端两端只读的文件名、正文断言已通过，但后续测试清理超时；M8ba 补齐测试启动的 Files 会话退出和原独立位置清理，原失败按机型本机复跑通过。完整云端验收仍延期，不能据此宣布系统清理或历史 Quick Look 读访问占用根因已修复。原协调锁、保存期限和结果断言保持。

证据分见[实施与失败调查](../archive/2026-h2/APPLE_MOBILE_FILES_INVESTIGATION_HISTORY.md)、[后续验证历史](../archive/2026-h2/RELEASE_VALIDATION_HISTORY.md)及[移动主计划](APPLE_MOBILE_MACOS_PARITY_DEVELOPMENT_PLAN_ZH.md)。真实 NAS、正式签名和真机继续按末尾条件验收。

## 已核实的平台差异

- 早期 SDK 核查确认 `NSFileProviderReplicatedExtension`、临时目录、下载副本清理、
  `waitForChanges` 与 `waitForStabilization` 支持 iOS 16，最低版本继续保持 17。
- `NSFileProviderDomain.userInfo`、外接卷、隐藏位置与管理器的 disconnect/reconnect
  是 macOS 专有 API，不能用 iOS 版本判断冒充支持。移动域使用稳定标识关联自己的映射记录。
- `supportsSyncingTrash` 在 iOS 18 才可设置；17 的行为必须按实际项目能力和回调核对。
  不能把 Mac 的赋值直接移植，也不能把移动端“最近删除”假装成 NAS 回收站。
- iOS 没有 `preserveDirtyUserData`/`preserveDownloadedUserData` 两种域移除模式。
  因此退出账号和暂停位置不能自动删除系统域或本机副本。若提供移除位置，须先检查
  可观察的未完成写回与系统同步结果，并明确说明本机副本/未保存改动的后果；不得承诺
  Mac 独有的保留模式。NAS 中文件的删除仍是独立的系统文件操作。

依据为本机 Xcode 26.5 SDK `FileProvider.framework/Headers/NSFileProviderDefines.h`、
`NSFileProviderDomain.h` 与 `NSFileProviderManager.h` 的声明及可用性；相关在线说明见
[Apple File Provider](https://developer.apple.com/documentation/fileprovider)。这些可用性证据
不等于真实设备已通过注册或写回测试。

## 必要配置、数据与回滚

新增 `.mobile.files` 扩展，复用 M8b 的移动 App Group 和共享会话组，主 App 身份、
最低系统版本、密码存储、NAS API 与第三方依赖不变。正式签名需为该新目标配置同组权限。
将可复用 File Provider 行为提取到现有 Apple Package 的独立模块，Mac 保留原 principal
class 和平台默认依赖，移动注入账号、受保护存储与系统适配；不能维护第二份写回算法。

移动映射记录独立保存原账号身份、NAS 范围及系统域编号，复用既有映射/路径/写回存储
处理业务状态。重新登录可使用同一身份的新会话；更换账号、地址或信任边界时旧位置
停止远端访问并保留恢复资料。系统回调必须重新验证当前绑定，不能根据过期的 UI 选择写入。
原 Mac 存储不迁移；移动端按当前开发格式实现，不维护旧开发数据兼容分支。

回滚停用新增移动入口和扩展嵌入，保留尚未结束的任务与副本供恢复；不得通过自动移除
域完成回滚而静默删除用户编辑。Mac 可回退到提取前引用，其持久格式与域身份应始终相同。

## 维护与验收顺序

1. 提取共享运行时与系统回调；保持 Mac 行为，编译核对 iOS 17 与现有 SDK 的实际可用性。
2. 实现原账号绑定、域注册/列表/暂停及读取、按需下载和缓存。根项目不依赖网络显示，
   真实读取仍须检查账号、权限和会话；验证进程重启、迟到回调与取消。
3. 接入创建、编辑写回、改名、移动、冲突与删除。沿用原副本、版本、权限、互斥与
   未知结果恢复；分别处理系统操作与主 App 的账号/位置生命周期。
4. 单独执行集成审查和只读对抗复核，运行共享/Mac 回归，以及两种模拟器的行为与
   实际系统入口测试。真实调度、设备文件保护、正式权限和 NAS 测试再列具体的
   `PENDING_USER_VALIDATION` 条件，不能以缺少设备中止其他源码工作。

非目标：Finder 菜单、外接卷迁移、桌面登录项、多窗口与未经平台支持的常驻运行。
iPhone 和 iPad 的业务范围相同，位置管理与确认采用各自原生布局。

## 独立集成与只读对抗复核

当前负责人在实现之外复核原 Mac 与提取后的差异、两端组合根和恢复流程：Mac
保留原 principal class、域身份、存储格式和默认依赖；共享枚举、缓存与写回算法只保留
一份。曾发现公开协议的默认异步实现遮蔽具体 actor 的状态方法，使移动请求被错误拒绝；
已移除该默认实现，在只读测试替身中显式拒绝，并补实际类型/协议两条调用路径回归。

每个系统域绑定原账号身份、NAS 范围与证书信任。每次请求前后及在途观察均检查
原绑定、共享会话、暂停与配置损坏，不能用旧缓存继续访问。退出和信任变化只撤销
远端访问，不自动删除系统副本。编辑与删除分别确认，冲突不自动覆盖，未知结果不
自动重发；恢复操作持有同一映射的写互斥。停止有内容的修改须先由系统导出成功，
取消导出不算成功；系统移除先拒绝未完成记录，再关闭远端访问、移除及回读结果。

系统位置必须由用户启用，生产代码没有设置测试自动启用模式。模拟器首次浏览时，
系统可能已显示位置开关为开，但域仍未启用并提示打开 App；通过“编辑位置”关闭再
开启该测试提供器后，两端均完成真实读取与写回。正式测试明确覆盖这个系统操作，
没有使用私有方法或放宽系统权限。

Mac 最终 Release 主 App 与 File Provider 已构建通过并确认 x86_64/arm64，未安装
或启动成品。复核由当前负责人独立进行，没有调用另一模型，没有真实 NAS 写入。

## 当前非复制式适配

M8aa 的全新两端对照提供了可用的只读路径，本片采用非复制式 iOS 系统适配，并继续
复用 ProviderRuntime 的枚举、下载、原版本比较、实际权限、写前记录、未知结果和
删除校验。Mac 保留现有复制式入口；NAS 请求、主 App/扩展身份、共享权限、最低版本
和语言范围均不变，不新增并行只读入口或自动权限降级。

必要新增状态是每个移动文件位置的受保护本地副本元数据，保存文件身份、路径、
取回时的内容/元数据版本及摘要。远端刷新不得覆盖有本机修改的副本，不能把新读到
的远端版本冒充原位编辑基线。记录位于已有移动专属共享容器，完整文件保护并排除
备份，不含登录凭据。移动尚未发布，不迁移旧开发格式；旧测试位置须沿原保存副本/
移除保护处理，不自动删除已注册位置、未保存文件或恢复记录。回滚恢复原平台入口，
保留新副本与记录供用户导出，不回滚 NAS 内容。

负责人单一修改共享平台桥接/本地副本存储、移动 Files 入口与位置控制、相关测试、
必要双语提示及工程生成。验收必须包括原三项两端系统 UI、缓存和原版本保护、
重复/未知写恢复、删除/移除及共享/Mac 回归；不能由最小只读样例替代正式验收。
恢复原删除仅排除该删除自身的待处理记录，不放行其他未完成写或后来编辑；已确认
原删除后才清理旧错误标记及未变化副本。位置移除仍拒绝未完成删除。文件与目录
两种丢失回执恢复均已实际验证只删除一次，相关 62 项单元全部通过。
