# macOS 语义基线下的 Windows 与 Apple 移动端对齐总控计划

## 决策摘要

macOS 是 Files、Photos、Chat、Download Station、NAS 管理、桌面云盘与安全行为的业务语义
基准。Windows 的目标是完整业务语义对齐；iPhone/iPad 的目标是移动专项计划中明确的
核心或受限用户结果。Android 不属于本计划的实施线，除非另有明确授权。

当前状态见[开发进度](../progress/STATUS.md)，能力边界见[平台功能矩阵](../progress/PLATFORM_MATRIX.md)，
已结束的阶段性账本见[跨端功能对齐历史](../archive/2026-h2/CROSS_PLATFORM_PARITY_HISTORY.md)。

## 基本规则

- 只读参考范围：`apple/Apps/DsmMac/**`。发现需要修改此范围时停止当前切片并请求用户
  明确授权，不能顺手修复。
- 共享 Apple Package 可做向后兼容的增量修改，但必须运行 macOS 回归；“未改 macOS App
  文件”不能替代共享 Package 的 macOS 验证。
- Windows 使用 WinUI/Fluent、键鼠、触控、窗口、文件资源管理器和系统通知习惯；移动端
  使用 SwiftUI、系统返回、触控、分享、Files/Photos 和移动后台规则。
- 不能从 macOS UI 复制悬停、右键、双击、菜单栏或常驻进程到移动端；不能从移动页面存在
  推断 Windows 业务语义已对齐。
- 私有 API 缺口不能用猜测请求、解析 UI 文案或复制 macOS 内部实现填补。

## 对齐账本

每个实施切片开始前维护一条账本，至少记录：

| 字段 | 要求 |
| --- | --- |
| macOS 证据 | 源文件、协议或测试路径；仅引用可复核仓库事实。 |
| 目标平台结果 | Windows 完整语义，或 iPhone/iPad 明确的核心/受限移动替代。 |
| 交互转换 | 键鼠/窗口或触控/系统分享/返回方式，及不可用能力。 |
| 契约依赖 | 官方 API、私有 API 记录、版本、权限、失败语义和降级。 |
| 安全级别 | 只读、普通写、高风险写、认证/证书、后台、跨 NAS 或系统集成。 |
| 验证等级 | 源码、自动化、构建、真机、发布；未验证项写 `PENDING_USER_VALIDATION`。 |
| 非目标 | 后续或非目标能力及取舍理由。 |

“页面存在”或“工程构建”都不等于功能对齐。帐本针对用户可完成的主流程，不为范围外能力
创建隐性实现 DAG。

## 依赖顺序

### 1. 契约与安全基线

1. 固定公开 API 名称、版本、参数、认证方式和错误映射；
2. 记录私有 API 的证据等级、能力探测、权限、副作用、失败语义和降级；
3. 对写操作建立确认、权限、重复提交保护、提交未知处理和最终状态复查；
4. 固定 profile、会话、证书、能力、导航、缓存和任务的隔离边界。

### 2. 用户主流程

按登录与会话、Files、传输、Photos、Chat、Download Station、只读 NAS/套件摘要的顺序
推进。Windows 逐步达到完整业务语义；移动端按“用户目标 → 移动替代 → 不可用能力 →
降级”记录。

### 3. 平台系统集成

- Windows：Explorer、Cloud Files、通知、托盘、安装和外接卷；
- macOS：Finder、File Provider、App Group、Keychain、签名、公证、升级与回退；
- iPhone/iPad：系统选择器、分享、前后台、网络切换、分栏、键盘和辅助功能。

系统集成在源码/自动化完成后由用户在受控设备验证。没有真机不是独立源码切片的阻塞，
但未验证高风险入口不得默认启用。

## 质量门

| 范围 | 必须执行 |
| --- | --- |
| 每个切片 | `git diff --check`、相关契约/fixture 脱敏/本地化与聚焦测试。 |
| Apple 共享层 | `swift test --package-path apple` 与 macOS 回归。 |
| Apple 移动端 | iPhone 和 iPad 模拟器构建；页面五态和可访问性检查。 |
| Windows | 托管 Runner 的 x64、ARM64、xUnit 与 WinUI XAML。 |
| Android 交叉影响 | 仅在契约改变时评估 Android，不得擅自修改 Android。 |
| 高风险路径 | 构建/实机前执行认证、证书、后台、跨 NAS、File Provider/Cloud Files 和私有 API 的只读对抗复核。 |

每次完成后进行独立集成审查。审查不降低断言、不删除既有测试、不把真实环境缺失改为
静默跳过；未执行的设备项目使用 `PENDING_USER_VALIDATION` 和明确前置条件。

## 文件所有权与并发

- Shell、路由、组合根、共享模型、Repository 接口、工程文件、资源、契约、平台矩阵和
  状态页是集成热点；一个切片必须声明唯一修改范围。
- 多人或多代理并行时，不同时写同一文件；写入前重新检查目标差异，发生并发变化时先合并
  上下文，不用旧版本覆盖新内容。
- 不新增平行实现、临时兼容层、专有工作流、重复抽象或无关重构。
- 变更 Bundle ID、包名、签名、权限、最低系统版本、依赖、数据格式或公开契约前，必须
  先说明必要性、影响、迁移和回滚并取得用户批准。

## 验收与交付

每个交付报告必须包括实际改动、关键决策、真实命令及结果、未验证风险、工作区状态和
下一独立切片。真实设备、正式签名、entitlement、系统注册、特定硬件和 NAS 条件无法
获得时，写明：

1. 前置条件；
2. 用户操作步骤；
3. 预期用户可见结果；
4. 允许回传的脱敏失败信息；
5. 受影响范围与入口当前关闭状态。

## 长期非目标与决策门

- 不以对齐任务顺手修改 macOS App；
- 不为矩阵齐全复制未验证的私有写请求；
- 不把 Windows 变成 macOS 视觉克隆，或把 iPhone/iPad 变成缩小桌面版；
- 不把真实环境、签名或用户设备缺失称为构建通过或发布完成；
- 不在没有独立产品、契约、安全和验收决策前推进后续能力。
