# Windows 独立测试包验收清单

本清单对应固定 `main/a521ccb5` 的 macOS 业务基线及本轮 Windows W0–W9 实现。范围和源码证据见[Windows 计划](../development/WINDOWS_MACOS_PARITY_DEVELOPMENT_PLAN_ZH.md)，实际命令、结果和包摘要见[验证历史](../archive/2026-h2/RELEASE_VALIDATION_HISTORY.md)。这是测试版验收，不能视为正式签名、发布或全部真实设备已经通过。

本轮最终包位于 `windows/dist/20261016-172411/`，提供 x64、ARM64 ZIP、各自 SHA-256，以及 `validation/` 中的生产源码清单、逐项回归结果和原生退出定位依据。使用该目录的最终包，不用前序中间包代替。

## 运行与回退

1. 根据设备选择 x64 或 ARM64 ZIP，比较附带的 SHA-256，将整个压缩包解压到新的独立目录。保留旧包，不覆盖原目录。
2. 手动运行 `LanStash.App.exe`。包包含所需 .NET 与 Windows App Runtime；生成包时不会安装或启动应用，也不带合成账号。独立目录只隔离程序文件，同一 Windows 用户仍共享应用身份和本机设置；不要同时运行旧包和新包。
3. 英语与简体中文可在本机设置切换；未固定语言时跟随系统，其他系统语言回退英语。语言设置独立于 NAS 账号。
4. 使用可丢弃的数据和专用测试账号。首先完成只读、权限拒绝和正常流程，再执行对应风险入口的专项验收。不要在唯一副本或生产系统上测试删除、覆盖、权限和电源操作。
5. 回退前结束或导出未完成的 Office 编辑及录音副本，处理尚未结束的传输。保留本机恢复资料；旧包不得接管新流程或覆盖无法读取的恢复格式。登录配置及 Cloud Files v10 不做本轮格式迁移。

源码仍在 `main` 的未提交工作区时，`build-info.json` 会如实显示基线提交和 modified 状态。交付目录中的源码清单另记录本轮文件摘要；基线提交本身不能唯一代表这些未提交修改。

以下保护与实际接口、账号/对象权限、明确操作和结果检查共同生效。它们不是 DSM/build 精确版本白名单，也不要求普通套件账号额外读取系统管理信息。

Cloud Files 保留 v10 日志边界。移动或删除丢回执、回读中断后，旧记录没有可用于重新认领操作的接受事实；即使路径消失或目标出现，也继续保留未知记录及本机内容。刷新不会重复移动/删除、自动继续下一步或清理本机副本。目录创建另有明确的“使用现有目录继续同步”，它只选择后续同步目标，不声称本次创建已成功。

Office/WPS 的预览组件和媒体编解码器取决于本机安装情况；没有组件时使用本机应用打开副本。虚拟机控制台需要本机可用的 Microsoft Edge WebView2 Runtime；ZIP 不包含该浏览器运行时，缺少时控制台会提示安装，其他模块仍可使用。便携包的 Explorer、通知、外接卷、休眠和物理 ARM64 行为均需单独验证。

完整原生测试曾在照片场景出现原生退出。后续调用栈和阶段记录定位到测试用合成 PNG 在 UI 回调中编码导致 XAML 重入；移至后台后，中英文原失败场景、快速预览及重复幻灯片专项通过，生产 Photos 逻辑没有因该问题改动。原始失败和后续结果分别见验证历史，合成通过仍不替代真实 NAS、系统编解码器或设备验收。PHOTO-05 同时检查反复切换来源、关闭重开预览及展开收起侧栏，若退出则记录发生阶段和脱敏 Windows 错误类别。

不要发送密码、验证码、Cookie、SID、SynoToken、DID、私钥、真实主机/文件路径、消息/日志正文、原始 HAR、PCAP、DSM 响应或恢复数据库。截图先移除账号、地址、路径和内容；日志只保留复现所需的脱敏错误。
